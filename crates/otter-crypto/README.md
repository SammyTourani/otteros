# otter-crypto

OtterOS's own cryptography, written from scratch: SHA-256/384/512, HMAC, HKDF,
and the ChaCha20-Poly1305 AEAD. `#![no_std]` + `alloc`, `#![forbid(unsafe_code)]`,
zero external dependencies (DECISIONS.md D2, D22, D27) -- the hash, MAC,
key-derivation and AEAD primitives TLS 1.3 will need (a later brief), proven
against FIPS/RFC test vectors and Project Wycheproof before any network code
uses them.

## Layout

| Module | What it does |
| --- | --- |
| `ct` | Best-effort constant-time helpers: `Choice`, `ct_eq`, `select_u8`, `Zeroizing<T>` |
| `hash` | The `Hash` trait (so HMAC/HKDF/TLS can pick SHA-256 or SHA-384 by cipher suite) and `Digest` |
| `sha256` | SHA-256 (FIPS 180-4) |
| `sha512` | SHA-512 and SHA-384 (share one 64-bit compression function, different IV/truncation) |
| `hmac` | HMAC (RFC 2104), generic over `Hash` |
| `hkdf` | HKDF-Extract/-Expand (RFC 5869), generic over `Hash` |
| `chacha20` | The ChaCha20 block function and keystream (RFC 8439 sections 2.3/2.4) |
| `poly1305` | Poly1305 (RFC 8439 section 2.5), 26-bit-limb accumulator |
| `aead` | AEAD_CHACHA20_POLY1305 (RFC 8439 section 2.8): `seal_in_place`/`open_in_place` |

Secret-dependent code avoids secret-indexed table lookups and secret-dependent
branches (`ct::ct_eq`, `poly1305`'s final reduction); see `ct`'s module doc for
the honest caveats of doing this in safe Rust.

## Testing

```sh
cd crates
cargo test -p otter-crypto                                  # unit + integration tests
cargo clippy -p otter-crypto --tests -- -D warnings          # lint
cargo build -p otter-crypto --target x86_64-unknown-none     # proves it's genuinely no_std
cargo run -p otter-crypto --release --example throughput     # MB/s, for the record
```

Every primitive's unit tests hardcode its own FIPS/RFC vectors (180-4, 2104,
4231, 5869, 8439) directly, including RFC 8439 Appendix A.3's eleven Poly1305
edge cases. Three integration test files need vectors fetched and generated by
tooling (not committed as raw JSON, so the tests need no JSON parser):

```sh
../scripts/gen-crypto-vectors.py   # -> tests/vectors/*.txt
```

That script downloads Project Wycheproof's HMAC-SHA-256/384/512,
HKDF-SHA-256/384/512 and ChaCha20-Poly1305 vectors (SHA-256-pinned) and
converts them to compact pipe-delimited fixtures, and separately cross-checks
this crate's SHA-256/384/512 against Python's `hashlib` for a seeded-random
message at every length 0-1100 bytes (catches padding-boundary bugs).
