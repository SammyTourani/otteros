# Brief M0-T1 — bootable hello + harness

## Goal
Starting from a repo that contains only docs, create the kernel crate and the build/test harness so that:
- `gmake iso` builds build/otteros.iso via Limine (hybrid: UEFI + legacy BIOS).
- `gmake test` boots headless in QEMU (UEFI via OVMF); the kernel prints `[ok] boot` on serial, runs the in-kernel test runner (>= 3 trivial tests), prints `[ok] tests passed (N)`, exits QEMU via isa-debug-exit with the success code; make exits 0. Must finish in < 90 s.
- `gmake bios-test` does the same via the legacy BIOS boot path (no OVMF).
- `gmake panic-test` boots with cmdline `test panic`; the kernel panics deliberately, prints `PANIC at file:line: msg` on serial and exits with the failure code; the make target asserts that failure was reported and itself exits 0.
- `gmake shot` boots headless in normal mode, waits for the framebuffer banner (serial line `[ok] fb banner`, or 25 s), takes a QMP `screendump` in PNG format to artifacts/shot.png, then terminates QEMU.
- `gmake run` opens a visible QEMU window (cocoa) with serial on stdio, for humans.

## Environment (verified on this machine)
- macOS 26.5 arm64 (Mac Mini M4). Homebrew at /opt/homebrew. qemu-system-x86_64 (TCG only, no HVF for x86), xorriso, mtools, gmake installed.
- OVMF: /opt/homebrew/share/qemu/edk2-x86_64-code.fd (read-only pflash unit 0) and edk2-i386-vars.fd (copy into build/ as a writable pflash unit 1).
- Rust: rustup at /opt/homebrew/opt/rustup/bin, toolchains in ~/.rustup, proxies in ~/.cargo/bin. Nightly is installed with rust-src, llvm-tools-preview, target x86_64-unknown-none. Pin the exact installed nightly date in rust-toolchain.toml (`rustup show`).
- No `timeout` binary (use `gtimeout` or Python subprocess timeouts). BSD sed. Python 3 available; Pillow is NOT installed and you must not pip-install anything.

## Approach (DECISIONS D1–D6 apply)
1. Reference material: the official Limine Rust template, `git clone --depth=1 https://github.com/limine-bootloader/limine-rust-template third_party/limine-rust-template` (third_party is gitignored). Reuse its ideas: cargo config for `x86_64-unknown-none` (static relocation model, kernel code model, no SSE/red-zone), build.rs passing `linker-x86_64.ld`, Limine request markers/sections, the ISO recipe, limine.conf syntax. Adapt, don't paste blindly. Limine binaries: clone the newest `vN.x-binary` branch of https://github.com/limine-bootloader/limine (check `git ls-remote --heads`; canonical mirror https://codeberg.org/Limine/Limine if GitHub fails) into third_party/limine and build the host tool with `make -C third_party/limine`. The Makefile must fetch these automatically when missing.
2. kernel/ is its own cargo project (Cargo.toml, .cargo/config.toml, build.rs, linker script, src/). `#![no_std] #![no_main]`. Modules: `arch::x86_64::port` (our own `inb/outb` via `core::arch::asm!`), `serial` (16550 on 0x3F8: init, write byte/str, `kprint!/kprintln!` via `core::fmt::Write`), `framebuffer` (from the Limine framebuffer response: clear to a dark colour, draw glyphs from an embedded public-domain 8x8 or 8x16 bitmap font, write a banner such as "OtterOS  M0  hello from ring 0" plus the resolution; record the font's licence in THIRD_PARTY_NOTICES.md), `qemu` (`exit(success: bool)` via port 0xf4 with codes 0x10/0x11), `panic` handler, `tests` (custom_test_frameworks runner with >= 3 `#[test_case]`s: arithmetic, serial write, framebuffer bounds). Use the `limine` crate for requests (base revision 3, framebuffer, HHDM, memory map, and the command line via `ExecutableCmdlineRequest` if the crate version has it, else via the executable/kernel file response's `cmdline()`).
3. Mode selection: parse the Limine cmdline; `test` -> run tests then exit; `test panic` -> deliberate panic; otherwise print the banner, print `[ok] fb banner` on serial, then `hlt` loop. The Makefile generates two configs (build/limine-normal.conf, build/limine-test.conf, and a panic variant) and builds the ISO variant it needs, or uses one ISO per mode; pick the simplest robust option.
4. Harness: `scripts/env.sh` (PATH exports, `set -a` style), `scripts/qemu.py` (Python 3, stdlib only): `--mode {run,test,shot} --firmware {uefi,bios} --iso PATH --timeout N --expect-failure`. It launches `qemu-system-x86_64 -M q35 -m 512M -cpu qemu64 -no-reboot -serial file:artifacts/serial.log -device isa-debug-exit,iobase=0xf4,iosize=0x04 -qmp unix:build/qmp.sock,server,nowait` plus `-display none` (test/shot) or `-display cocoa -serial stdio` (run) and the pflash drives for UEFI. isa-debug-exit makes QEMU exit with `(value<<1)|1`: 33 = success, 35 = failure. For test: poll the process with a timeout, tail serial to stdout, map 33 -> exit 0, anything else -> exit 1 (inverted when `--expect-failure`). For shot: poll artifacts/serial.log for `[ok] fb banner` (max 25 s), then speak QMP over the unix socket (`qmp_capabilities`, then `screendump` with `filename` absolute and `format: "png"`), wait for the file, terminate QEMU. GNUmakefile wires: build, iso, test, bios-test, panic-test, shot, run, clean, and a `deps` target that fetches Limine.
5. README.md: what OtterOS is, the AI-authored claim (written by Claude agents; humans run the loop and supply hardware), how to build/run, a milestone table linking PLAN.md.

## Acceptance (run all; report exit codes)
- `source scripts/env.sh && gmake iso && ls -la build/otteros.iso`
- `gmake test` -> exit 0; artifacts/serial.log contains `[ok] boot` and `[ok] tests passed`
- `gmake bios-test` -> exit 0
- `gmake panic-test` -> exit 0 and serial.log contains `PANIC at`
- `gmake shot` -> artifacts/shot.png exists, > 5 KB; `sips -g pixelWidth -g pixelHeight artifacts/shot.png` prints a sane resolution; convert with `sips -s format bmp artifacts/shot.png --out build/shot.bmp` and check with a few lines of Python that the pixel bytes are not all one value
- `cargo clippy --manifest-path kernel/Cargo.toml` -> no warnings
- `gmake test` a second time -> still exit 0 (deterministic)
