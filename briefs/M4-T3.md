# Brief M4-T3 — shared memory, message channels with handle passing, named services

## Goal
Processes can share memory and exchange messages, pass descriptors to each other, and find each
other by name. This is the transport for the display server protocol (next task) and later for the
agent's tool broker.

## Applies
D2, D10, D16, D17.

## Where things are
fds, pipes and poll: kernel/src/fs/vfs/fd.rs, kernel/src/fs/pipe.rs, kernel/src/syscall/poll.rs.
VMM and frames: kernel/src/mm/. New: kernel/src/ipc/{mod,shm,channel,service}.rs, tests in
kernel/src/test_cases/ipc.rs and user/utest.

## Design
1. Shared memory: `shm_create(size)` returns an fd for a zeroed object backed by PMM frames (max
   64 MiB); `mmap_fd(fd, len, prot)` maps it USER + NX (+ WRITABLE when requested and allowed);
   `munmap`. Frames are reference-counted across fds and mappings and freed exactly once when the
   last reference goes.
2. Channels: `chan_pair()` returns two fds of a bidirectional, message-oriented link: messages up to
   64 KiB, 256 queued per direction, order preserved, `chan_send(fd, buf, len, handles, nhandles)`
   passes up to 4 fds (the receiver gets fresh fds referring to the same objects),
   `chan_recv(fd, buf, cap, handles_out, cap)` returns the byte length and handle count, EMSGSIZE
   when the buffer is too small (message stays queued), EAGAIN for non-blocking empty reads,
   hang-up when the peer closes. Channels participate in poll().
3. Services: `svc_register(name)` returns a listener fd (names up to 32 bytes, one owner each,
   EADDRINUSE otherwise, released when the owner closes or dies); `svc_connect(name)` returns the
   client end and queues the server end on the listener; `svc_accept(listener)` returns it.
   Listeners are pollable.
4. libotter: `shm::Shm::create/map`, `ipc::Channel { send, recv, send_with_handles }`,
   `ipc::Listener::register/accept`, `ipc::connect`, plus a tiny serialization helper for fixed
   little-endian message structs (no serde).
5. Resource limits: per-process fd limit applies; a process that dies mid-send leaves no dangling
   handles; a slow receiver cannot make the kernel allocate without bound (queue cap → EAGAIN).

## Tests
Kernel (`#[test_case]`, >= 8): shm refcount frees frames at the right moment; mapping flags; channel
ordering and boundaries; EMSGSIZE leaves the message queued; handle passing gives the receiver a
working fd (a pipe passed across); hang-up on peer close; service name uniqueness and release on
owner death; poll wakes on channel readability. Userspace utest (>= 5): two processes exchange 1000
messages through a named service with checksums; a shared-memory ring buffer written by one process
and read by another; a pipe passed over a channel carries data; killing the server makes the client
see hang-up; 64 MiB shm map succeeds and 65 MiB fails.
