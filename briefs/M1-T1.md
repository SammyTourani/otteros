# Brief M1-T1 — GDT, TSS, IDT, exception handlers, double fault on an IST stack

## Goal
CPU tables owned by the kernel (Limine's are temporary), every exception vector handled with a useful
register dump, page faults report CR2, and a double fault lands in its own handler on an IST stack
instead of triple-faulting the machine.

## Applies
DECISIONS D2 (no `x86_64` crate: write descriptors, `lgdt/lidt/ltr` and stubs yourself), D5, D6.

## Where things are
`git ls-files kernel` shows the layout. Shared modules live in kernel/src/lib.rs (both binaries use
them); normal entry kernel/src/main.rs; test entry kernel/src/test_main.rs with `#[test_case]`s in
kernel/src/tests.rs; port I/O in kernel/src/arch/x86_64/port.rs. New code goes under
kernel/src/arch/x86_64/: gdt.rs, idt.rs, interrupts.rs (stubs), trap.rs (TrapFrame + dispatcher).

## Design
1. GDT: null; kernel code 0x08 (64-bit, DPL0); kernel data 0x10; user data 0x18 (DPL3); user code
   0x20 (64-bit, DPL3); TSS system descriptor at 0x28 (16 bytes). This order matters later for
   `sysret` (user SS = base+8, user CS = base+16). Load with `lgdt`; reload CS with a far return
   (`push 0x08; lea rax,[rip+1f]; push rax; retfq; 1:`); DS/ES/SS = 0x10, FS/GS = 0; `ltr 0x28`.
2. TSS: one static TSS. RSP0 = top of a dedicated 64 KiB static kernel stack (16-byte aligned) for
   later ring-3 transitions. IST1 = top of a 32 KiB double-fault stack. IST2 = 32 KiB for NMI and
   machine check. I/O map base = size of the TSS (no IOPB).
3. IDT: 256 gates. Vectors 0–31 interrupt gates DPL0, except vector 3 (breakpoint) DPL3 so user code
   can use `int3` later. Vector 8 uses IST1; vectors 2 and 18 use IST2. Vectors 32–255 also route
   to the dispatcher (they become IRQ handlers in a later task); for now they log
   `[trap] unexpected vector N` and return. Interrupts stay disabled in this task: no `sti`.
4. Stubs: a macro generates 256 `#[unsafe(naked)] unsafe extern "C" fn` stubs with
   `core::arch::naked_asm!`. Vectors that push a CPU error code (8, 10, 11, 12, 13, 14, 17, 21, 29,
   30) push nothing extra; all others push a 0 dummy error code. Every stub then pushes its vector
   number and jumps to a common stub that pushes the 15 GPRs, moves `rsp` into `rdi`, calls
   `extern "C" fn trap_dispatch(frame: *mut TrapFrame)`, pops the GPRs, `add rsp, 16` (vector +
   error code), `iretq`. Alignment check: the CPU aligns RSP to 16 before pushing its 5- or 6-word
   frame; with the dummy error code both cases leave RSP ≡ 0 mod 16, vector push makes 8, 15 GPRs
   (120 bytes) make 0 again, so `call` enters the dispatcher SysV-aligned (rsp ≡ 8 mod 16).
   `#[repr(C)] struct TrapFrame { r15..rax (in push order), vector, error_code, rip, cs, rflags,
   rsp, ss }` lives in trap.rs; `size_of` is 22 * 8.
5. Dispatcher: breakpoint → increment an `AtomicUsize` counter, log `[trap] breakpoint rip=0x..`,
   return. Page fault → read CR2, decode the error code (present, write, user, reserved, ifetch),
   print `EXCEPTION: PAGE FAULT at 0x<cr2 hex, no leading zeros> (flags) rip=0x..` and a full register
   dump, then panic. Double fault → `EXCEPTION: DOUBLE FAULT` + dump, then panic. Every other
   exception → mnemonic + dump + panic. Vector ≥ 32 → log and return. The existing panic handler
   already exits QEMU with the failure code in test mode.
6. Boot wiring (both binaries, in the shared init path): serial init, then `gdt::init()`, then
   `idt::init()`, then everything else. Log `[gdt] loaded` and `[idt] loaded (256 gates)`.
7. Fault modes via the cmdline (D6):
   - `test pagefault` → after init, `read_volatile` one byte from virtual address 0xdead_beef_000
     (unmapped: far above RAM, not in the HHDM, not the kernel). Expect PAGE FAULT with that CR2.
   - `test doublefault` → deterministic double fault without needing a guard page: set RSP to an
     unmapped address and execute `int3` (`mov rsp, 0xdead_0000_000; int3`). The CPU cannot push
     the trap frame → #PF → cannot push again → #DF on IST1 → our handler prints and panics.
     (A real stack-overflow guard page and `stackoverflow-test` arrive with the VMM task later.)
8. Harness: add `--expect-serial REGEX` to scripts/qemu.py (`re.search` over artifacts/serial.log
   after QEMU exits; missing → failure), then GNUmakefile targets `fault-test` (cmdline
   `test pagefault`, `--expect-failure --expect-serial 'PAGE FAULT at 0xdeadbeef000'`) and `df-test`
   (cmdline `test doublefault`, `--expect-failure --expect-serial 'DOUBLE FAULT'`). Reuse the
   panic-test plumbing (one small test ISO per cmdline is fine). `-no-reboot` is already set: a
   triple fault makes QEMU exit without the string, which is precisely what these targets catch.
9. Tests (`#[test_case]`, in addition to the existing 3): `gdt_selectors_loaded` (CS == 0x08,
   SS == 0x10 read via `mov {}, cs`), `tss_loaded` (`str` == 0x28), `tss_ist1_valid` (non-zero,
   16-byte aligned, within the static stack), `idt_exception_gates_present` (32 gates present,
   vector 8 has IST index 1, vector 3 has DPL3), `breakpoint_returns` (`int3` increments the
   counter by exactly 1 and execution continues), `breakpoint_twice` (+2), `trapframe_layout`
   (size 176, offsets of vector/rip match the push order). Total ≥ 10.

## Acceptance (run all; report exit codes)
- `source scripts/env.sh && gmake test` → 0; serial shows `[gdt] loaded`, `[idt] loaded`, `[ok] tests passed (N)` with N ≥ 10
- `gmake fault-test` → 0; serial contains `PAGE FAULT at 0xdeadbeef000` and `PANIC at`
- `gmake df-test` → 0; serial contains `DOUBLE FAULT`
- `gmake bios-test` → 0; `gmake panic-test` → 0; `gmake shot` → 0 (banner still renders)
- `cargo clippy --manifest-path kernel/Cargo.toml` → 0 warnings; `gmake build` warning-free
- every `unsafe` block has a `// SAFETY:` comment (grep it yourself)
