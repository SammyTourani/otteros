# Brief M8-T1 — `otter-crypto` part 1: SHA-2, HMAC, HKDF, ChaCha20-Poly1305 (pure crate, host-tested)

## Goal
The first half of OtterOS's own cryptography: the hash, MAC, key-derivation and AEAD primitives
TLS 1.3 needs, written from scratch in safe Rust, constant-time where secrets are involved, and
proven against official test vectors before any network code uses them.

## Applies
D2 (no crypto crates of any kind), D22 (constant-time, RFC + Wycheproof vectors), D27.

## Scope and boundaries (another agent is working in kernel/ and user/ concurrently)
Touch only `crates/otter-crypto/` (add it to the `crates/` workspace members in crates/Cargo.toml),
`scripts/gen-crypto-vectors.py`, and an appended THIRD_PARTY_NOTICES.md section for the Wycheproof
test data. Do not edit kernel/, user/, GNUmakefile, other crates or other docs. Do not run gmake or
QEMU.

## Design
1. `#![no_std]`, `#![forbid(unsafe_code)]`, zero dependencies. A small `ct` module: `Choice`,
   `ct_eq(&[u8], &[u8]) -> bool` without early exit, conditional select, and `Zeroizing<T>`
   wrappers that overwrite secret buffers on drop (use `core::ptr::write_volatile` is unsafe, so
   instead overwrite through a `black_box`ed slice and document the best-effort nature).
2. SHA-256, SHA-384, SHA-512: streaming `update`/`finalize` and one-shot helpers; message length
   limits handled; block function readable and fast enough (report MB/s).
3. HMAC over each hash (streaming), HKDF-Extract and HKDF-Expand (RFC 5869) generic over the hash.
4. ChaCha20 (RFC 8439: 32-bit block counter, 96-bit nonce), Poly1305 (26-bit limbs or u64/u128
   arithmetic, final reduction constant-time), the ChaCha20-Poly1305 AEAD (RFC 8439 §2.8):
   `seal_in_place(key, nonce, aad, buf) -> tag`, `open_in_place(key, nonce, aad, buf, tag) ->
   Result<(), AeadError>` with a constant-time tag comparison and the plaintext wiped on failure.
5. A `Hash` trait (output size, block size, new/update/finalize) so TLS can select SHA-256 or
   SHA-384 by cipher suite.

## Test data
`scripts/gen-crypto-vectors.py` (Python stdlib only) downloads Project Wycheproof vector files
(from the C2SP/wycheproof GitHub repository: chacha20_poly1305_test.json and the hmac_sha256/384/512
and hkdf_sha256/384/512 test files; pin SHA-256 hashes of the downloads in the script) and converts
them into compact line-based fixtures committed under `crates/otter-crypto/tests/vectors/`. It
also emits cross-check fixtures from Python's hashlib/hmac for random messages of every length
0..1100 bytes (seeded).

## Tests (host `cargo test`, >= 40 test functions, plus every Wycheproof case)
FIPS 180-4 / RFC 6234 examples for all three hashes (empty, "abc", the 448- and 896-bit messages,
one million 'a'); hashlib cross-checks for every length 0..1100 (catches padding bugs at block
boundaries); streaming split at every offset equals one-shot; RFC 4231 HMAC vectors; RFC 5869 HKDF
vectors; RFC 8439 vectors for the ChaCha20 block function, keystream, Poly1305 (incl. the edge-case
vectors in Appendix A.3) and the AEAD; Wycheproof: every valid case passes, every invalid case is
rejected; tampered ciphertext, tag and AAD are rejected and leave the buffer zeroed; ct_eq
behaviour.
