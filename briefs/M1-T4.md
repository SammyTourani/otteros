# Brief M1-T4 — virtual memory: our own page tables, guard-paged kernel stack

## Goal
The kernel owns CR3. It builds fresh 4-level page tables from the Limine memory map, maps itself
W^X, reproduces the HHDM, exposes a map/unmap/translate API for everything that follows (MMIO,
user processes, shared memory), and runs on a kernel stack with a guard page so a stack overflow
is reported instead of silently corrupting memory.

## Applies
D2 (no `x86_64` crate: page-table entries, CR0/CR3/CR4/EFER access, `invlpg` are yours), D3, D4,
D5, D6, D13, D14, D15 (the layout; read it).

## Where things are
kernel/src/mm/{addr,hhdm,bitmap,pmm,heap}.rs exist. Limine requests live where M0 put them
(`git grep -n Request kernel/src`); you will additionally need the executable address request
(kernel phys/virt base) and the linker-script symbols for section bounds (edit
kernel/linker-x86_64.ld to export `__text_start/__text_end`, `__rodata_start/__rodata_end`,
`__data_start/__data_end` (data + bss), each 4 KiB aligned). New code: kernel/src/mm/paging.rs
(entries, flags, table walk), kernel/src/mm/vmm.rs (`AddressSpace`, kernel space init, CR3
switch), kernel/src/mm/kstack.rs (kernel stacks + guard registry), kernel/src/arch/x86_64/cr.rs
(CR0/CR2/CR3/CR4, EFER rdmsr/wrmsr, invlpg, tlb flush). Set `kaslr: no` in the generated
limine.conf variants.

## Design
1. `paging.rs`: `PageTableEntry(u64)` with a `PageFlags` bitset (PRESENT, WRITABLE, USER,
   WRITE_THROUGH, NO_CACHE, ACCESSED, DIRTY, HUGE, GLOBAL, NO_EXECUTE) — `bitflags` is allowed by
   D2 if you want it. `PageTable` = 512 entries, 4 KiB aligned. Tables are always accessed through
   the HHDM. Helpers: index extraction for each level, `next_table(&entry) -> Option<&mut
   PageTable>`, `next_table_or_create(entry, pmm)` allocating a zeroed frame.
2. `vmm.rs`: `AddressSpace { pml4: PhysAddr }` with `map_4k(virt, phys, flags)`,
   `map_2m(virt, phys, flags)`, `map_range(virt, phys, len, flags)` (uses 2 MiB pages when both
   sides are 2 MiB aligned and the run is long enough, else 4 KiB), `unmap(virt) -> Option<PhysAddr>`
   (frees nothing; caller owns frames; `invlpg`), `translate(virt) -> Option<(PhysAddr, PageFlags,
   PageSize)>`, `activate()` (write CR3). Mapping an already-mapped page is a kernel bug: panic
   with both addresses.
3. `init_kernel_space()`: allocate a PML4; map the kernel image from the executable address
   response: text RX (no WRITABLE, no NX), rodata R + NX, data/bss RW + NX, all GLOBAL; map the
   HHDM for every memory-map entry except BAD_MEMORY (usable, reserved, ACPI, bootloader
   reclaimable, executable, framebuffer) with RW + NX + GLOBAL using 2 MiB pages where possible;
   also map the region from 0 up to the highest entry end rounded to 1 GiB so MMIO holes below that
   (LAPIC 0xFEE00000, I/O APIC 0xFEC00000, HPET) are reachable through the HHDM. Before switching:
   set EFER.NXE (MSR 0xC0000080 bit 11), CR0.WP, CR4.PGE. Switch CR3, then print
   `[vmm] switched to kernel page tables (pml4=0x..)`. The framebuffer must still work afterwards
   (banner code paths unchanged: it lives in the HHDM).
4. `kstack.rs`: a bump allocator over the kernel dynamic region (D15) hands out
   `KernelStack { guard: VirtAddr, bottom, top }` = one unmapped 4 KiB guard page followed by N
   mapped frames (allocate frames from the PMM, map RW + NX + GLOBAL). Registry: a fixed-size
   static table of guard ranges with `find_guard(addr) -> Option<..>`. After `init_kernel_space()`,
   allocate a 64 KiB boot stack and switch to it in a small asm shim (`mov rsp, top; call
   kmain_after_vmm`) — never return into the old frame. Also point the TSS RSP0 at this new stack
   top via the existing `set_rsp0` helper.
5. Fault reporting: the double-fault handler (D14 emergency path) reads CR2 and, if it falls in a
   registered guard page (or within 4 KiB below a stack bottom), prints
   `EXCEPTION: DOUBLE FAULT — kernel stack overflow (guard page 0x..)`. Add cmdline mode
   `test stackoverflow` (D6): `#[inline(never)]` recursion with a 1 KiB local touched each level
   until the guard is hit. New target `gmake stackoverflow-test` with `--expect-failure
   --expect-serial 'kernel stack overflow'`.
6. Tests (`#[test_case]`, ≥ 9 new): `translate(kernel text symbol)` equals the executable
   physical base plus the offset; `translate(hhdm + 0x1000)` == 0x1000; text pages are not WRITABLE
   and not NX, rodata pages are NX, data pages are WRITABLE + NX; map a fresh PMM frame at a
   dynamic-region address, write through it, read the same bytes through the HHDM alias; unmap it,
   translate returns None; a 2 MiB mapping translates with `PageSize::Huge`; CR3 equals our PML4;
   PML4 entries 256..511 are populated exactly as the kernel space's (identity of the two
   halves for a freshly created empty `AddressSpace::new_user()` which copies them); the current
   stack's guard page translates to None while the stack's first page translates to Some;
   `find_guard(current_stack.guard)` is Some.

## Acceptance (run all; report exit codes)
- `source scripts/env.sh && gmake test` → 0; serial shows `[vmm] switched` and `[ok] tests passed (N)` with N ≥ 36
- `gmake stackoverflow-test` → 0; serial contains `kernel stack overflow`
- `gmake fault-test`, `gmake df-test`, `gmake pmm-fault-tests`, `gmake bios-test`, `gmake panic-test`, `gmake shot` → 0 each (banner still renders after the CR3 switch)
- `gmake lint` → 0; `gmake build` warning-free
- every `unsafe` block has a `// SAFETY:` comment
