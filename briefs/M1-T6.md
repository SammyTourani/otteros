# Brief M1-T6 — PS/2 keyboard: i8042 controller, IRQ 1, scancode decoding, end-to-end typing test

## Goal
Typing on the keyboard produces key events the kernel can consume, driven by interrupts, decoded
into characters with modifiers, and proven end to end by QEMU injecting keystrokes.

## Applies
D2 (no `pc-keyboard` crate), D5, D9, D14.

## Where things are
IRQ plumbing: kernel/src/arch/x86_64/{irq,ioapic,lapic}.rs (`irq::register`, `ioapic::set_redirect`,
`irq::isa_to_gsi`). ACPI summary: kernel/src/acpi/ (FADT boot-architecture flags tell whether an
8042 exists on ACPI ≥ 2 machines). New code: kernel/src/drivers/ps2/{mod,i8042,keyboard,scancode,ring}.rs.
Harness: scripts/qemu.py already speaks QMP for screenshots.

## Design
1. `ring::SpscRing<T, N>`: lock-free single-producer/single-consumer ring (IRQ pushes, kernel pops)
   with atomics; overflow drops the newest byte and counts it.
2. `i8042`: ports 0x60/0x64 with bounded waits (never spin forever: a 100 ms PIT/ticks budget, then
   log and give up). Sequence: if the FADT says no 8042 (revision ≥ 2, IA-PC boot flags bit 1
   clear), log `[kbd] no i8042 per ACPI` and skip; else disable both ports, flush output buffer,
   read config byte, controller self-test (0xAA → 0x55), port-1 test (0xAB → 0x00), enable port 1,
   set config: IRQ1 on, translation ON (so we get scancode set 1), reset device (0xFF → 0xFA then
   0xAA), set LEDs. Log `[kbd] i8042 ok`.
3. IRQ: ISA IRQ 1 → GSI via `isa_to_gsi` → I/O APIC redirect to vector 33, level/polarity from
   the override flags, unmasked. Handler reads 0x60 and pushes into the ring. No decoding in IRQ
   context.
4. `scancode`: set-1 state machine with 0xE0 prefix, make/break, into
   `KeyEvent { key: Key, pressed: bool, mods: Modifiers }` where `Key` is an enum covering
   letters, digits, punctuation, F1–F12, arrows, Home/End/PgUp/PgDn/Insert/Delete, Enter,
   Backspace, Tab, Escape, Space, modifiers, Caps/Num/Scroll lock. Modifiers tracked from
   make/break (left/right shift, ctrl, alt, caps lock toggle). `KeyEvent::to_char()` for a US
   layout honouring shift and caps lock. Caps-lock LED updated through the controller.
5. `keyboard`: `poll_event() -> Option<KeyEvent>`, `read_char_blocking() -> char` (`hlt` between
   polls), counters (irqs, dropped). Normal mode: after the banner, echo typed characters to the
   framebuffer and serial with a `> ` prompt line so a human can try it in `gmake run`.
6. End-to-end test: `scripts/qemu.py --send-keys TEXT` waits for `[kbd] ready` on serial, then
   sends each character via QMP `send-key` (qcode names; handle shift for capitals by sending
   `shift` together with the key), 30 ms apart. A `#[test_case] keyboard_e2e` prints `[kbd] ready`,
   blocks until it has read 5 chars (with a 5 s ticks timeout → fail), and asserts they equal
   `hello`. `gmake test` passes `--send-keys hello`.
7. Tests (`#[test_case]`, ≥ 9 new): ring push/pop/wrap/overflow; decoder: `a` make/break events;
   shift+`a` → 'A'; caps lock toggles case; E0-prefixed Right Arrow decodes; ctrl modifier set
   while held and cleared on break; digits with shift give symbols; i8042 self-test passed (flag);
   the keyboard GSI redirect entry is unmasked with vector 33; keyboard_e2e as above.

## Acceptance (run all; report exit codes)
- `source scripts/env.sh && gmake test` → 0; serial shows `[kbd] i8042 ok`, `[kbd] ready`, `[ok] tests passed (N)` with N ≥ 55
- `gmake bios-test`, `gmake fault-test`, `gmake df-test`, `gmake stackoverflow-test`, `gmake pmm-fault-tests`, `gmake panic-test`, `gmake shot` → 0 each
- `gmake lint` → 0; `gmake build` warning-free
- every `unsafe` block has a `// SAFETY:` comment
