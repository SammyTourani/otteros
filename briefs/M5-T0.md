# Brief M5-T0 — `otter-http`: URLs, HTTP/1.1 client, chunked bodies, server-sent events (pure crate)

## Goal
A transport-agnostic HTTP/1.1 client library that `fetch`, the page viewer and the Claude client
(agent mode) will all use, proven on the Mac over plain TCP and over OtterOS's own TLS 1.3
(`otter-tls`) against real websites.

## Applies
D2 (no HTTP crates), D27 (pure no_std + alloc crate, host-tested, zero external dependencies; path
dependencies on other crates in crates/ are fine).

## Scope and boundaries (another agent works in kernel/ and user/ concurrently)
New crate `crates/otter-http/`, test helpers under `scripts/http-test-server.py`. Do not touch
kernel/, user/, GNUmakefile or other crates' sources. Do not run gmake or QEMU.

## Design
1. URL parsing (RFC 3986 subset): scheme http/https, host (DNS name, IPv4, bracketed IPv6), port with
   scheme defaults, path, query, fragment dropped from requests; percent-encoding helpers; relative
   reference resolution for redirects and page links.
2. Sans-I/O client: `Request { method, url, headers, body }` serialised with Host, User-Agent
   `OtterOS/0.1`, Connection, Content-Length; a `ResponseParser` fed bytes incrementally that yields
   status line, headers (case-insensitive lookup, folded/duplicate handling), and the body via
   Content-Length, `Transfer-Encoding: chunked` (with trailers) or read-until-close; size limits on
   header block (64 KiB) and line length; malformed input is an error value, never a panic.
3. Redirect handling helper (301/302/303/307/308, max 5, method rules) for callers that loop.
4. Server-sent events (the WHATWG event-stream format): an incremental parser yielding events
   (`event`, `data` joined with newlines, `id`, `retry`), handling CR, LF and CRLF line endings and
   chunks split anywhere — the Claude Messages API streams this way.
5. A tiny blocking convenience layer behind a `Transport` trait (read/write), so host tests can use
   `std::net::TcpStream` and, for HTTPS, `otter-tls` driven over that stream.

## Tests (host)
- URL parsing table (≥ 30 cases incl. edge cases), relative resolution per RFC 3986 §5.4 examples.
- Response parsing fed one byte at a time and in random splits: fixed length, chunked with
  extensions and trailers, close-delimited, 204/304 without bodies, malformed status/header/chunk
  size → errors.
- SSE: the WHATWG spec examples, split at every byte offset, multi-line data, comments, CRLF.
- Local server: `scripts/http-test-server.py` (Python stdlib http.server) serving fixed, chunked,
  redirecting and SSE endpoints on 127.0.0.1; end-to-end GETs over std TCP.
- Live (`#[ignore]`, run with `--ignored` in acceptance): `GET https://example.com/` through
  otter-tls + otter-http returns 200 and a body containing "Example Domain"; follows a redirect
  from `http://github.com` → `https://github.com/` (report the chain).

## Acceptance (run all; report exit codes)

- `cargo clippy -p otter-http --tests -- -D warnings` -> 0; `cargo build -p otter-http --target x86_64-unknown-none` -> 0
