# Brief M6-T2 — the SMP scheduler: threads on every CPU, IPIs, TLB shootdown, locks audited

## Goal
After M6-T1 every CPU is online but threads run only on the BSP. Run threads on all CPUs with
per-CPU run queues and work stealing, wake sleepers on the right CPU with reschedule IPIs, keep
page tables coherent with TLB shootdowns, and make every lock SMP-safe. PLAN M6: `gmake check`
runs with `-smp 4` and an 8-thread parallel stress test passes 20 runs in a row. Otter's
multi-threaded matrix kernels (M7) depend on this.

## Applies
D4, D25, CLAUDE.md conventions (`// SAFETY:` on every `unsafe`, zero warnings), M6-T1's `smp` API
(`current_cpu`, `run_on`, IPIs, per-CPU areas). Never run git checkout/restore/reset/stash/clean.
Run `kernel-review` (Sonnet) on the diff before reporting and fix its findings.

## Design
1. Per-CPU run queues (a lock each) and a per-CPU idle thread; `sched::spawn` places a new thread on
   the least-loaded CPU; an idle CPU steals from the busiest queue (only threads not currently
   running; keep affinity for threads that just ran unless another CPU idles). Timer ticks drive
   preemption on every CPU (each CPU's LAPIC timer).
2. Wakeups: waking a thread enqueues it on its last CPU (or the waker's if idle) and sends a
   reschedule IPI when the target CPU is running something of lower priority or idling in `hlt`.
3. Thread lifecycle across CPUs: a thread's stack and state must not be freed while another CPU is
   still switching away from it (use the switch-completion handshake / reaper on the right CPU);
   join and kill work across CPUs.
4. Locks: `IrqMutex` = interrupts off + a real spinlock (ticket or test-and-test-and-set with
   `pause`); `sched::Mutex`/`Semaphore`/`WaitQueue` correct when the waker and sleeper are on
   different CPUs (no lost wakeups: check-and-sleep atomically with respect to wake). Audit every
   `static` (PMM, heap, VFS stubs, console, net, random's IRQ ring index (fetch_add), timers) and
   document in the report which ones were changed.
5. TLB shootdown: every change to a mapping that another CPU may have cached (kernel mappings, a
   process's address space whose threads ran elsewhere, kernel stack slots) invalidates on all
   relevant CPUs before the change is considered done (IPI with the address range, target acks;
   full flush above a threshold). Provide `vmm::kernel_remap_4k(virt, phys, flags)` (map or
   remap one kernel page and shoot down) for tests and later drivers.
6. `smp::current_cpu()` stays valid across preemption (read per-CPU state with interrupts off or
   through GS in one instruction).

## Required tests (kernel `#[test_case]`s in kernel/src/test_cases/smp_sched.rs)
- threads_spread: 8 CPU-bound threads for ~300 ms each record the CPUs they ran on; the union
  covers >= 3 of 4 CPUs and every thread made progress.
- mutex_exact: 4 threads x 20,000 read-modify-write increments under `sched::Mutex` (with a short
  spin inside the critical section) give exactly 80,000, and the threads ran on >= 2 CPUs;
  the same with `IrqMutex`.
- ping_pong: two threads exchange 5,000 wakeups through semaphores within 30 s, observed on
  different CPUs.
- no_lost_wakeups: 1 producer and 3 consumers pass 10,000 items through a semaphore-guarded
  queue; the consumed sum equals the produced sum, bounded time.
- tlb_shootdown: a kernel page mapped to frame A (bytes 0xAA) is read on every CPU via `run_on`
  (warming their TLBs), remapped to frame B (0xBB) with `kernel_remap_4k`, then every CPU reads
  0xBB (never 0xAA). QEMU's per-vCPU software TLB makes this test meaningful under TCG.
- stress_20_runs: 20 rounds of 8 threads mixing mutex, semaphore, sleep, heap allocation and
  spawn/join of short-lived threads; every round finishes with consistent counters, no leaks
  (PMM free-frame count and stack slots back to the baseline).
