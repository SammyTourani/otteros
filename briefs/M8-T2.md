# Brief M8-T2 — `otter-crypto` part 2: AES-128/256-GCM (constant-time + AES-NI/PCLMUL) and X25519

## Goal
The remaining symmetric AEAD and the key exchange TLS 1.3 needs: AES-GCM with a constant-time
software path and a hardware path, and X25519, all proven against RFC, NIST and Wycheproof vectors.

## Applies
D2, D22 (constant-time; hardware path only when CPUID reports it), D27.

## Scope and boundaries (other agents work in kernel/ and user/ concurrently)
Touch only `crates/otter-crypto/` and `scripts/gen-crypto-vectors.py` (extend it), plus the
THIRD_PARTY_NOTICES.md Wycheproof section if the file list changes. Do not run gmake or QEMU.

## Design
1. Unsafe policy: the crate stays `#![deny(unsafe_code)]` (change from forbid) with
   `#[allow(unsafe_code)]` only inside a `hw` module that wraps the x86_64 intrinsics
   (AES-NI, PCLMULQDQ, CPUID) behind safe functions, each with a `// SAFETY:` comment. Runtime
   detection through CPUID (no std): AES-NI (leaf 1 ECX bit 25), PCLMULQDQ (leaf 1 ECX bit 1),
   cached in an atomic. On non-x86_64 hosts the hw module compiles to nothing.
2. Software AES: constant-time bitsliced implementation (BearSSL `aes_ct64` style: 64-bit words,
   four blocks in parallel, bitsliced S-box circuit), key schedule for 128 and 256-bit keys,
   encryption only (GCM and CTR need no decryption). No lookup tables indexed by secret data.
3. GHASH: constant-time software multiplication in GF(2^128) (BearSSL `ghash_ctmul64` style,
   carry-less multiply via masked integer multiplications), and a PCLMULQDQ path with the
   reduction; AES-GCM (NIST SP 800-38D) with 96-bit nonces only (reject others with an error), tag
   length 16, `seal_in_place`/`open_in_place` matching the ChaCha20-Poly1305 API, constant-time tag
   check, plaintext wiped on failure. A common `Aead` trait over both AEADs for TLS.
4. X25519 (RFC 7748): field arithmetic mod 2^255-19 with 51-bit limbs and u128 products, Montgomery
   ladder with constant-time conditional swap, clamping, `x25519(scalar, u)` and
   `x25519_base(scalar)`, rejection of the all-zero shared secret (return an error, as TLS requires).

## Tests (host)
- aarch64 (native): software AES against FIPS-197 vectors; GCM against the McGrew-Viega/NIST test
  cases (all 18 standard ones); Wycheproof aes_gcm_test.json (96-bit IV groups); X25519 RFC 7748
  vectors including the 1 and 1000 iteration ladders (and 1 000 000 behind an `#[ignore]` flag),
  Wycheproof x25519_test.json with every flag handled (low-order points give the zero-secret error);
  software GHASH against a naive bit-by-bit reference for random inputs.
- x86_64 under Rosetta: `cargo test -p otter-crypto --target x86_64-apple-darwin` runs the same
  suite with the AES-NI/PCLMUL path enabled, and a differential test asserts hardware and software
  paths agree on 10 000 random (key, nonce, aad, plaintext) cases.
