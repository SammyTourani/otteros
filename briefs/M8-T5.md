# Brief M8-T5 — `otter-tls`: a TLS 1.3 client (RFC 8446), proven against real servers from the Mac

## Goal
A from-scratch TLS 1.3 client that completes verified handshakes and exchanges application data with
real-world servers. It is a sans-I/O state machine, so it is tested on the Mac over ordinary TCP
now, and OtterOS's own TCP stack drives it later with no changes.

## Applies
D2, D22 (TLS 1.3 only; any verification failure aborts), D27.

## Scope and boundaries (another agent works in kernel/ and user/ concurrently)
New crate `crates/otter-tls/` (path dependencies on otter-crypto and otter-x509 only), test
scripts under `scripts/tls-*`, fixtures under `crates/otter-tls/tests/`. Do not touch kernel/,
user/ or GNUmakefile. Do not run gmake or QEMU.

## Design
1. Sans-I/O API: `ClientConnection::new(config, server_name, now_unix, rng)`; `read_tls(&[u8])`
   feeds received bytes; `take_outgoing() -> Vec<u8>` returns bytes to send; `process()` yields
   events (HandshakeComplete { suite, alpn, peer display name }, ApplicationData, PeerClosed,
   Alert); `send(&[u8])`; `close()`. The caller supplies randomness through a trait and the current
   time. No threads and no allocation beyond `alloc`.
2. ClientHello: legacy_version 0x0303, 32 random bytes, 32-byte legacy session id (middlebox
   compatibility), suites TLS_AES_128_GCM_SHA256 / TLS_AES_256_GCM_SHA384 /
   TLS_CHACHA20_POLY1305_SHA256 ordered by `config.prefer_chacha` (true when the CPU lacks AES-NI),
   extensions: server_name, supported_versions (0x0304 only), supported_groups (x25519), key_share
   (x25519), signature_algorithms (ecdsa_secp256r1_sha256, ecdsa_secp384r1_sha384,
   rsa_pss_rsae_sha256/384/512), signature_algorithms_cert (adds rsa_pkcs1_sha256/384/512 and the
   ECDSA schemes), ALPN from the config. No PSK, no early data.
3. Handshake processing: ServerHello validation (supported_versions, offered suite, echoed session
   id, x25519 key share, TLS 1.2/1.1 downgrade sentinels rejected), HelloRetryRequest (cookie echo;
   requested group other than x25519 is a clear error; transcript `message_hash` substitution),
   key schedule per §7.1 with HKDF-Expand-Label, transcript hashing with the suite's hash,
   EncryptedExtensions (ALPN), Certificate → otter-x509 `verify_server_chain` with the host name and
   time, CertificateVerify over the 64-space prefix and server context string with an allowed
   scheme, server Finished verified in constant time, client Finished sent, then application keys.
   Post-handshake: NewSessionTicket discarded, KeyUpdate honoured (respond when requested),
   close_notify both ways, alerts mapped to errors.
4. Record layer: content types, AEAD nonce = IV XOR sequence number, inner content type and
   zero padding removal, record size limits (2^14 plaintext, 2^14 + 256 ciphertext), handshake
   messages split across and coalesced within records, change_cipher_spec records ignored during
   the handshake, anything unexpected is a fatal alert.

## Tests (host)
- Local interop: `openssl s_server` from the Homebrew OpenSSL 3.6 CLI with the M8-T4 test PKI
  (crates/otter-x509/tests fixtures) and `-tls1_3 -ciphersuites` forcing each suite in turn; a small
  echo exchange per suite; a HelloRetryRequest case if openssl can be made to issue one (e.g.
  `-groups` preferring a group the client supports only after retry, or a cookie), otherwise
  documented.
- Negative: wrong host name, untrusted root, expired leaf (validate at a later time), a byte flipped
  in a record by an in-test TCP shim (bad_record_mac), truncated handshake, server selecting a suite
  that was not offered (scripted fake server).
- Live (`#[ignore]`, run with `-- --ignored` during acceptance, skipped cleanly when offline): full
  handshake plus `GET / HTTP/1.1` status line from example.com, www.cloudflare.com, www.google.com
  and github.com; handshake only (no request) to api.anthropic.com. Report the suite each server
  chose and the handshake time.
- Also build for `x86_64-unknown-none`.

## Acceptance (run all; report exit codes)
- `cd crates && cargo test -p otter-tls` -> 0; `cargo test -p otter-tls -- --ignored` -> 0 with network
- `cd crates && cargo clippy -p otter-tls --tests -- -D warnings` -> 0; `cargo build -p otter-tls --target x86_64-unknown-none` -> 0
- zero external dependencies
