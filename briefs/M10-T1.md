# Brief M10-T1 — xHCI host controller, USB keyboard, USB mass storage (kernel)

## Goal
The laptop boots from a USB stick and keeps its data partition there; its keyboard or an external
one may be USB. Drive the xHCI controller with the host-tested crates `otter-xhci` (TRBs, rings,
contexts, registers) and `otter-usb` (descriptors, requests, HID boot keyboard to scan codes,
BOT/SCSI), enumerate devices on the root ports, bind a boot keyboard (feeding the existing
keyboard decoder) and a bulk-only mass-storage stick (a block device). Acceptance tests:
`kernel/src/test_cases/usb.rs` (orchestrator, unchanged; its header is the API).

## Applies
D2 (path dependencies otter-xhci, otter-usb, otter-part), D15 (uncached MMIO window), CLAUDE.md
conventions (`// SAFETY:` everywhere, `[xhci]`/`[usb]` log prefixes). Never run git
checkout/restore/reset/stash/clean. Do not edit the oracle.

## Design (xHCI 1.2 section numbers)
1. Discovery: PCI class 0x0C/0x03/0x30; map BAR0 (64-bit) through `mm::mmio`; enable memory space
   and bus mastering. Capability registers via `otter_xhci::regs::parse_capabilities`.
2. BIOS handoff (7.1.1) before touching the controller: set HC OS Owned, wait up to 1 s for HC BIOS
   Owned to clear (log and continue if it does not), clear SMI enables in USBLEGCTLSTS.
3. Init (4.2): USBCMD.R/S=0 and wait HCHalted; HCRST and wait for it and CNR to clear; CONFIG.MaxSlotsEn;
   DCBAA (entry 0 = scratchpad pointer array when Max Scratchpad Buffers > 0, each buffer one
   page, all zeroed); command ring (ProducerRing, CRCR with RCS=1); one event ring segment
   (EventRing, ERSTSZ=1, ERDP, ERSTBA written last); USBCMD.R/S=1. DMA memory from the same
   allocator virtio uses, physically contiguous, zeroed.
4. Completion: poll the event ring from a `usb` kernel thread (every 1 ms, like the net thread);
   interrupts can come with the MSI-X work later. Commands wait for their Command Completion
   Event (matched by TRB address) with a timeout.
5. Ports (4.3): for each connected port (CCS), USB2 ports (from the Supported Protocol capability)
   get a port reset (PR, wait PRC), USB3 ports train by themselves; read the speed; Enable Slot;
   Address Device with an input context (slot: root port, speed, context entries 1; EP0: control,
   max packet from `Speed::default_ep0_max_packet`, CErr 3, a transfer ring); GET_DESCRIPTOR(device,
   8) then Evaluate Context if bMaxPacketSize0 differs (full speed); full device and configuration
   descriptors via `otter_usb::desc`; SET_CONFIGURATION; Configure Endpoint for the interface's
   endpoints (DCI, `interval()`, max packet, max burst from the companion). Log each device as
   `[usb] port 3: 0627:0001 hid keyboard (full speed)`.
6. HID boot keyboard (class 3/1/1): SET_PROTOCOL(boot), SET_IDLE(0); keep one Normal TRB of 8 bytes
   queued on the interrupt IN endpoint; each completed report goes through
   `otter_usb::hid::BootKeyboard::report` and the resulting set-1 bytes into the PS/2 keyboard's
   decoder input (add a `keyboard::inject_scancode(u8)` used by both paths), so `poll_event`
   returns USB keys too. Set the LEDs with SET_REPORT when Caps/Num Lock toggles.
7. Mass storage (class 8/6/0x50): Get Max LUN (stall means 0); per LUN INQUIRY, TEST UNIT READY
   (retry with REQUEST SENSE while "not ready", up to 5 s), READ CAPACITY(10) and (16) when the 10
   variant saturates; `UsbDisk` implements the block layer's device interface with READ/WRITE(10/16)
   from `otter_usb::msc`, transfers split at 64 KiB per TRB and chained (CH bit) within a TD,
   one request at a time (a sleeping mutex). BOT recovery (BOT 5.3.4): stall on a bulk pipe →
   CLEAR_FEATURE(HALT) (+ Reset Endpoint and Set TR Dequeue Pointer on the xHCI side); invalid or
   meaningless CSW → Bulk-Only Mass Storage Reset, then clear both halts.
8. Harness: `scripts/mkdisk.py --usbstick build/usbstick.img` (64 MiB, MBR, one FAT32 partition from
   LBA 2048 via mtools with HELLO.TXT); `scripts/qemu.py --usb` adds `-device qemu-xhci,id=xhci
   -device usb-kbd,bus=xhci.0 -drive if=none,id=stick,format=raw,file=build/usbstick.img
   -device usb-storage,bus=xhci.0,drive=stick`; `--send-keys` gains `--send-keys-after LINE`
   (default `[kbd] ready`); `gmake usb-test` boots a test ISO with cmdline
   `test testfilter=usb` using `--usb --send-keys hello --send-keys-after '[usbkbd] ready'`, and
   joins `scripts/check.sh`. The normal `test` machine stays without USB devices (a usb-kbd would
   take QMP keys away from the PS/2 tests).

## Acceptance
- `source scripts/env.sh && gmake check` → every target PASS including `usb-test` (the four usb
  tests pass).
- `gmake lint` clean. The report lists the `[xhci]` and `[usb]` boot lines.
