# Brief M5-T0e — `otter-tcp`: sans-I/O TCP (RFC 9293) as a pure crate

## Goal
A correct, robust TCP for IPv4 that the kernel's network stack (M5) drives with segments and a
clock, proven on the Mac by exact RFC scenario tests and a lossy-network simulation where two
instances must deliver byte streams perfectly. TLS 1.3 to api.anthropic.com (M8/M9) rides on it.

## Applies
D2, D27 (no_std + alloc, zero external dependencies; path dependency on `otter-net-proto` for
`Ipv4Addr` and `checksum::checksum` is allowed). No clock or randomness inside: time is a `now: u64`
in milliseconds passed by the caller; the initial sequence number is passed in.

## Design (crates/otter-tcp)
1. Codec (`segment.rs`): parse/encode the TCP header incl. options EOL, NOP, MSS, window scale,
   SACK-permitted, timestamps (unknown options skipped by length; malformed lengths → error);
   checksum over the IPv4 pseudo-header. Never panics on any input.
2. `Tcb` with every RFC 9293 state. API: `Tcb::connect(cfg, local, remote, iss, now)`,
   `Tcb::listen(cfg, local)`, `on_segment(&Segment, now)`, `poll_transmit(now) -> Option<OutSegment>`
   (call until None), `poll_timeout() -> Option<u64>` and `on_timer(now)`, `send(&[u8]) -> usize`
   (bounded send buffer), `recv(&mut [u8]) -> Result<usize, TcpError>` (Ok(0) = EOF after the
   peer's FIN), `close()` (FIN after queued data), `abort()` (RST), `state()`, `error()`
   (Refused, Reset, TimedOut). `Config`: MSS 1460, receive and send buffers 64 KiB, initial RTO
   1000 ms, min RTO 200 ms, max RTO 60 s, 6 SYN retries, 15 data retries, MSL 30 s, delayed-ACK
   40 ms (0 = off), Nagle on/off.
3. Behaviour: sequence arithmetic mod 2^32; RFC 9293 §3.10.7 segment-arrival processing incl.
   the acceptability table, out-of-window → ACK; out-of-order segments kept within the receive
   window and merged (overlaps trimmed); advertised window = free receive space, right edge never
   shrinks; segments ≤ min(peer MSS, usable window); RFC 6298 SRTT/RTTVAR/RTO with Karn's rule and
   exponential backoff; RFC 5681 Reno with RFC 6582 NewReno fast retransmit/recovery (3 duplicate
   ACKs), initial window 10 segments; zero-window persist probes with backoff; ACK every second
   full segment or after the delayed-ACK time; half-close in both directions; TIME_WAIT for 2×MSL,
   re-ACKing a retransmitted FIN; RST: in SYN-SENT only with an acceptable ACK (→ Refused);
   otherwise RFC 5961 (exact sequence → Reset, in-window → challenge ACK, else ignore); SYN in a
   synchronized state → challenge ACK; give up after the retry limits (→ TimedOut). Window scaling
   is parsed but not negotiated (window ≤ 65535) in this task.

## Tests (host; `cargo test -p otter-tcp`; ≥ 45 tests)
- Codec: round trip of random headers with options; checksums equal to an independent Python
  implementation's (fixtures generated by a script committed under the crate's `tests/`); byte-flip
  fuzzing (1,000 mutations per fixture) and every prefix never panic.
- Exact scenarios (assert the segments' flags/seq/ack/window/payload): active open with MSS option;
  passive open; simultaneous open (RFC 9293 Figure 8); SYN retransmit at 1, 2, 4, … s and TimedOut
  after 6 retries; RST answering SYN → Refused; data both ways with ACKs; out-of-order segments
  reassembled; duplicate segment re-ACKed; out-of-window segment → ACK; zero window → persist
  probes, transfer resumes when the window opens; fast retransmit after 3 duplicate ACKs; active
  close, passive close, simultaneous close (CLOSING); half-close with data still flowing the other
  way; TIME_WAIT expiry and FIN retransmission during TIME_WAIT; RST exact / in-window / outside;
  SYN in ESTABLISHED; ISS = 0xFFFF_FF00 transferring 1 MiB across the wrap; Nagle coalescing;
  delayed-ACK timer.
- Simulation (`tests/netsim.rs`): client and server `Tcb`s over a seeded simulated link with
  one-way delay 1–50 ms plus jitter, loss 0 / 1 % / 5 % / 20 %, 1 % duplication, reordering and a
  bandwidth cap. Each side writes random-size chunks (total 0 B – 256 KiB, some runs 1 MiB), then
  closes. Assert: both byte streams arrive exactly and in order, both sides see EOF, both reach
  CLOSED (after TIME_WAIT), no panic, finite simulated time (report the maximum). ≥ 400 seeds
  across the loss levels in the default run (under 60 s in debug); a 5,000-seed `#[ignore]` stress
  test. Throughput sanity: 0 % loss, 20 ms RTT, 100 Mbit/s link, 16 MiB transfer reaches
  ≥ 20 Mbit/s simulated goodput (the 64 KiB window allows ~26); with 1 % loss ≥ 5 Mbit/s.
- Robustness: random segments (random flags/seq/ack/payload/window) fed to a Tcb in every state,
  100,000 total: never panics; invariants hold (snd_una ≤ snd_nxt, buffers never exceed their
  capacity, the advertised right edge never moves left).
