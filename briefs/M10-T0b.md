# Brief M10-T0b — otter-xhci: the sans-I/O core of the xHCI driver

## Goal
Every laptop's USB ports sit behind an xHCI controller. The kernel driver (M10-T1) should be
glue: MMIO reads/writes and DMA memory. Everything that can be wrong without hardware lives here
and is host-tested: TRB encoding, producer and event rings with their cycle bits, slot/endpoint/
input/output contexts in 32- and 64-byte layouts, endpoint numbering and intervals, PORTSC bit
handling, capability registers and the extended-capability walk (BIOS handoff, protocol ports).
Crate `crates/otter-xhci`, passing `crates/otter-xhci/tests/oracle.rs` (orchestrator, unchanged;
its header is the exact API and the semantics the specification leaves open).

## Applies
D2, D27: `#![no_std]`, no `alloc` needed except `Vec` in `walk_extended_caps` (use `alloc`), zero
dependencies, `#![forbid(unsafe_code)]`: ring memory is `&[AtomicU32]` (the kernel builds that
slice over DMA memory), and TRB dword 3 (the one holding the cycle bit) is stored last with
`Ordering::Release` and loaded first with `Ordering::Acquire`. Add `otter-xhci` to
`crates/Cargo.toml` members. Modules `trb`, `ring`, `context`, `regs`, each under ~600 lines.
Never run git checkout/restore/reset/stash/clean. Tests only via `scripts/verify-crate.sh` or
`scripts/memguard.py`. Do not edit the oracle.

## Design notes
- Keep the bit positions in named constants (e.g. `TRB_TYPE_SHIFT`, `PORTSC_PED`), each with a
  comment citing the xHCI 1.2 section, so the kernel driver and reviewers can check them.
- `Trb(pub [u32; 4])`; builders are free functions in `trb`; `DataStage { None, Out, In }` sets
  the Setup Stage TRT field (0, 2, 3).
- `EpType` is `#[repr(u8)]` with the xHCI values (NotValid 0 .. InterruptIn 7) and `Default`
  NotValid; `Speed` derives Debug, Clone, Copy, PartialEq, Eq.
- `walk_extended_caps` follows next pointers (in dwords, relative to the current capability);
  0 ends the list, as does a `first` of 0; at most 64 entries.
