# Brief M3-T3 — VFS, ramfs root, devfs, file descriptors, pipes, file syscalls, libotter fs API

## Goal
Every process sees one file tree: `/` (writable ramfs populated from the initramfs), `/data` (the
FAT32 volume), `/dev` (devices). Processes use file descriptors for files, devices and pipes;
children inherit or receive redirected descriptors, which is what the shell and the M4 terminal
app need.

## Applies
D2, D14, D16 (negative errno), D17 (spawn, no fork), D18.

## Where things are
FAT32: kernel/src/fs/fat32/ (`Fat32Fs` API). initramfs: kernel/src/fs/initramfs.rs. Processes and
syscalls: kernel/src/proc/, kernel/src/syscall/, SYSCALLS.md. libotter: user/libotter. New code:
kernel/src/fs/vfs/{mod,path,mount,node,file,fd}.rs, kernel/src/fs/{ramfs,devfs,pipe}.rs, tests in
kernel/src/test_cases/vfs.rs and new checks in user/utest.

## Design
1. VFS: a `FileSystem` trait (root, statfs, sync) and `Node` trait (lookup, create, mkdir, unlink,
   rmdir, rename, readdir, read_at, write_at, truncate, stat, kind), reference-counted nodes. Mount
   table with longest-prefix matching; path resolution for absolute and relative paths (per-process
   cwd), `.` and `..` across mount points, repeated slashes, max path 1024, max component 255,
   ENOTDIR / ENOENT / EISDIR / ENOTEMPTY / EEXIST / EXDEV / ENAMETOOLONG as appropriate.
2. ramfs: in-memory tree (files are `Vec<u8>` or page lists), used as `/`; at boot, copy the
   initramfs contents into it (`/bin/*`, `/etc/motd`). devfs at `/dev`: `console` (reads keyboard
   bytes incl. the ANSI key sequences from M2-T4, writes to console + serial), `null`, `zero`,
   `random` (xorshift seeded from TSC and RDRAND when present; comment: replaced by the M8 DRBG),
   `vda`, `vda1` (block devices, read-only through devfs for now). FAT32 mounted at `/data` when
   a FAT32 partition is found (log `[vfs] mounted fat32 at /data`).
3. File descriptions and fd tables: an open file = node + offset + flags, shared on dup; per-process
   table of 64 fds; fds 0/1/2 point at /dev/console by default. Flags: O_RDONLY, O_WRONLY, O_RDWR,
   O_CREAT, O_TRUNC, O_APPEND, O_EXCL, O_DIRECTORY, O_CLOEXEC (no exec yet, but spawn honours it).
4. Pipes: 64 KiB ring buffer, blocking reads and writes on wait queues, EOF when all writers are
   closed, EPIPE (and no signal) when all readers are closed. A killed process closes its fds.
5. Syscalls (numbers appended in SYSCALLS.md, errno from D16): open, close, read, write (generalised
   from M2), lseek, fstat, stat, getdents (fixed-size records: inode no, kind, name), mkdir, unlink,
   rmdir, rename, chdir, getcwd, pipe, dup, dup2, sync, truncate/ftruncate, and `spawn` gains an
   optional `[stdin, stdout, stderr]` mapping (-1 = inherit). All user pointers go through usermem.
6. libotter: `fs::File` (open/create/read/write/seek/metadata/set_len), `fs::read_to_string`,
   `fs::write`, `fs::read_dir`, `fs::create_dir`, `fs::remove_file`, `fs::remove_dir`,
   `fs::rename`, `env::current_dir/set_current_dir`, `io::pipe()`, `process::Command`-style
   builder with stdin/stdout/stderr redirection, `sync()`.
7. Tests: kernel (`#[test_case]`, >= 10): path normalisation table; mount lookup; ramfs create/read
   /write/unlink; `..` out of `/data` returns to `/`; EXDEV on cross-mount rename; devfs null/zero;
   pipe EOF and EPIPE semantics; fd table dup/close sharing offsets; spawn with redirected stdout
   into a pipe returns the child's output; FAT32 via VFS equals direct FAT32 reads. Userspace utest
   (>= 8 new checks): write/read /tmp file on ramfs; write, sync and read back on /data; readdir of
   /bin lists init, sh, hello; cwd and relative paths; pipe between two processes (`hello` stdout →
   utest reads it); O_EXCL on an existing file gives EEXIST; unlink then open gives ENOENT; a
   300-entry directory on /data lists fully.
