# Brief M10-T2 — `gmake usb-image`: the boot stick with the model and the key placeholder

## Goal
The laptop demo boots from one USB stick that also carries Otter's model and the API key file
(D31). Build `build/otteros-usb.img`, a dd-able disk image: GPT (with protective MBR) holding one
FAT32 EFI System Partition labelled `OTTEROS` that contains Limine (UEFI and BIOS), the kernel,
the initramfs, `otter/model.otm` and an empty `config/anthropic.key`, with a limine.conf that
loads the model and the key as modules. Prove it boots in QEMU from the disk (not a CD) under
OVMF and SeaBIOS and that the kernel sees the modules. Update docs/HARDWARE.md.

## Applies
D5 (Limine), D7 (FAT32 data), D23 (the key: created by the human, never committed or logged),
D31. Never run git checkout/restore/reset/stash/clean. Do not touch existing tests.

## Design
1. `scripts/make-usb-image.py` (Python 3 stdlib + the mtools/limine CLIs already used by the
   build; no new Homebrew packages): size from `USB_IMAGE_MB` (default 512; the file is sparse),
   GPT written by the script (protective MBR, primary and backup headers and arrays with CRC32,
   one partition of type EFI System from LBA 2048 to the last usable LBA, name `OTTEROS`), the
   partition formatted FAT32 with `mformat` at the partition's offset (`-i img@@offset`), files
   copied with `mcopy`/`mmd`, then `limine bios-install` on the image (read Limine's docs for GPT:
   it uses the gap after the partition array). Contents:
   `/EFI/BOOT/BOOTX64.EFI`, `/limine-bios.sys`, `/boot/limine/limine.conf`,
   `/boot/otteros-kernel`, `/boot/initramfs.tar`, `/otter/model.otm` (`MODEL=` path, default
   `$OTTEROS_MODEL_DIR/SmolLM2-135M-Instruct.q8.otm`; `MODEL=none` omits it and its conf line),
   `/config/anthropic.key` (0 bytes), `/README-OTTEROS.txt` (three lines: what the stick is, how
   to put the key in config/anthropic.key from macOS Finder, that agent mode stays off while the
   file is empty).
2. limine.conf entry "OtterOS": the normal kernel, `module_path: boot():/boot/initramfs.tar`
   (cmdline `initramfs`), `module_path: boot():/otter/model.otm` (cmdline `model`),
   `module_path: boot():/config/anthropic.key` (cmdline `anthropic-key`).
3. Kernel: at boot log each module as `[boot] module <name>: <bytes> bytes` (for
   `anthropic-key` log only whether it is empty or present: `[boot] module anthropic-key: present`
   or `: empty`, never its bytes or length, D23). If M7-T5's module code already exists, extend it;
   otherwise add the minimal module listing.
4. `gmake usb-image` builds it; `gmake usb-image-test` boots it twice with `scripts/qemu.py`
   (a new `--disk IMAGE` option that attaches the image as the boot disk instead of `-cdrom`),
   OVMF and SeaBIOS, normal (non-test) kernel, and passes when serial shows
   `[boot] module model:` and `[boot] module anthropic-key: empty` within the timeout (use
   `--mode test` style expect-serial matching with a boot-to-prompt marker; add a `--expect-only`
   flag if qemu.py needs one to stop QEMU once all patterns matched). Add `usb-image-test` to
   `scripts/check.sh` with `MODEL=none` (fast) and keep a manual target with the real model.
5. docs/HARDWARE.md: step 1 becomes `gmake usb-image`, step 2 writes `build/otteros-usb.img`,
   a new "Agent mode" step explains copying the key into `config/anthropic.key` on the stick
   (Finder shows it as the OTTEROS volume), and that the key never leaves the stick except to
   api.anthropic.com over TLS.

## Acceptance
- `source scripts/env.sh && gmake usb-image-test` → exit 0 (both firmwares).
- `gmake check` → every target PASS including `usb-image-test`.
- `python3 -c` check in the report: the image's GPT CRCs validate (use the logic of
  crates/otter-part's oracle or `otter-part` itself via a tiny test) and `mdir -i
  build/otteros-usb.img@@1M ::/config` lists `anthropic.key` with size 0.

## Report
<=15 lines: files, the [check] table, the `[boot] module` lines, the image layout, deviations.
Do not commit.
