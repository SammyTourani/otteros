# Brief M2-T5 — make kernel thread creation and teardown fast

## Goal
The kernel suite takes ~130 s per boot under TCG and one test is a third of it:
`sched::create_and_join_1000_kernel_threads_sequentially` takes ~42 s, i.e. ~42 ms to create,
run, exit, join and reap one kernel thread. Every gate run pays this twice (UEFI and BIOS), and M6
(SMP) will create threads far more often. Find where the time goes and make the test at least 4x
faster (under 10 s on UEFI in the gate) without weakening anything: the test itself, the guard
pages / stack-overflow detection (`thread-stackoverflow-test`, `stackoverflow-test`), the leak
checks (1000 threads and 200 processes free every frame and stack slot), and the scheduler tests.

## Applies
CLAUDE.md conventions (`// SAFETY:` on every `unsafe`, zero warnings). Never run git
checkout/restore/reset/stash/clean. Do not edit any existing test.

## Method
1. Measure first: temporarily instrument (`time::uptime_ms` / TSC around each phase: stack slot
   allocation, page mapping, zeroing, TLB flushes, thread object allocation, first switch-in,
   exit, reaper, unmapping) and report per-phase costs for 100 threads. Remove the instrumentation
   afterwards (or keep it behind a `sched_profile` cmdline flag that is off by default).
2. Fix the dominant costs. Likely candidates: zeroing or mapping whole stacks eagerly (map lazily
   or reuse slots already mapped and zeroed only where needed), a full TLB flush (CR3 reload) where
   `invlpg` of the few affected pages suffices, the reaper waking on a timer instead of on exit,
   per-thread heap churn. Keep guard pages unmapped and verified.
3. The per-test durations the runner prints (`ok (N ms)`) are the evidence; report the ten slowest
   tests before and after.

## Acceptance
- `source scripts/env.sh && gmake check` → all targets PASS; the report shows
  `create_and_join_1000_kernel_threads_sequentially ... ok (N ms)` with N < 10000 on UEFI.
- `gmake lint` clean.

## Report
<=15 lines: files, the per-phase profile, before/after durations of the ten slowest tests, the
[check] table, deviations. Do not commit.
