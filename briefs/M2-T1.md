# Brief M2-T1 — kernel threads, preemptive scheduler, sleeping and synchronisation

## Goal
Multiple kernel threads run concurrently under a preemptive round-robin scheduler driven by the
timer tick, threads can sleep, block on wait queues and take sleeping mutexes, and the keyboard
reader blocks instead of polling. This is the substrate every process runs on.

## Applies
D2, D13 (no FPU state in kernel threads), D14, D15 (every kernel stack has a guard page), D17,
D19 (1 kHz tick; 10 ms timeslice).

## Where things are
Timer tick: kernel/src/time.rs (`on_tick`) and the IRQ path in kernel/src/arch/x86_64/{irq,trap}.rs.
Stacks: kernel/src/mm/kstack.rs (`allocate`, guard registry). TSS: `gdt::set_rsp0`. Locks:
kernel/src/sync.rs (IrqMutex). Keyboard consumer: kernel/src/drivers/ps2/keyboard.rs.
New code: kernel/src/sched/{mod,thread,context,runqueue,sleep,waitqueue,mutex,idle}.rs,
kernel/src/arch/x86_64/switch.rs (asm), tests in kernel/src/test_cases/sched.rs.

## Design
1. `Thread`: id (monotonic u64), name (`&'static str` or small String), state
   (Ready/Running/Blocked/Sleeping/Exited), kernel stack (`KernelStack` from kstack, 64 KiB),
   saved `rsp`, entry fn + arg, exit code, `ticks_run`. Stored as `Arc<Thread>`-like shared
   handles (write your own `Arc` or use `alloc::sync::Arc`; `alloc` is fine, it is not an OS crate).
2. Context switch (`switch.rs`): `switch_to(prev_rsp: *mut u64, next_rsp: u64)` in naked asm:
   push rbp, rbx, r12–r15; store rsp into `*prev_rsp`; load next rsp; pop; `ret`. A new thread's
   stack is pre-seeded so that the first `ret` lands in `thread_trampoline`, which enables
   interrupts, calls the entry, then `sched::exit_current()`.
3. Scheduler (`mod.rs`, `runqueue.rs`): a `VecDeque` ready queue behind an IrqMutex; `current()`;
   `spawn(name, fn, arg) -> ThreadId`; `yield_now()`; `exit_current() -> !`; `block_current()`
   (caller already holds nothing) and `wake(thread)`; `schedule()` picks the next Ready thread
   (idle thread if none) and switches. Preemption: `time::on_tick` decrements the timeslice and
   sets `need_resched`; the IRQ dispatch path, after EOI and with interrupts still disabled, calls
   `sched::preempt_if_needed()` which switches away from within the interrupt context (the
   interrupted thread's trap frame stays on its own kernel stack; when it is switched back to,
   it continues through the normal `iretq`). Update the TSS RSP0 to the incoming thread's kernel
   stack top on every switch (needed for ring 3 in the next task).
4. Idle thread: `hlt` loop, only chosen when the queue is empty; never counted in `ps` later.
5. Sleeping (`sleep.rs`): a sorted list (or binary heap) of (wake_tick, thread); `sleep_ms(ms)`
   blocks the current thread; `on_tick` moves due threads to Ready (wake-ups from IRQ context
   touch scheduler state only under the IrqMutex, never allocate, never log).
6. `WaitQueue`: `wait_until(|| cond)` (re-checks under the lock to avoid lost wake-ups),
   `wake_one`, `wake_all`. `Mutex<T>` (sleeping, built on WaitQueue, non-recursive; panics on
   re-entry by the same thread). `Semaphore`. Keep `IrqMutex` for IRQ-shared state.
7. Exit and reaping: an exited thread cannot free its own stack; a `reaper` step run by the
   next thread (or idle) frees stacks of exited threads. `join(id) -> exit code` via a WaitQueue.
8. Keyboard: `read_char_blocking` waits on a WaitQueue that the IRQ handler wakes (`wake_one`
   from IRQ context is allowed: it only enqueues). The `main.rs` echo loop becomes a kernel thread.
9. Boot: `sched::init()` turns the boot context into thread 0 ("main"); the rest of boot
   continues on it; the normal binary spawns the echo thread; the test binary runs the test
   suite on the main thread (tests spawn helpers).
10. Negative test: cmdline `test thread-stackoverflow` recurses inside a spawned thread; expect
    `kernel stack overflow` (proves guard pages work for non-boot stacks). Target
    `thread-stackoverflow-test`; add it to `gmake check`.
11. Tests (`#[test_case]`, ≥ 12 new): two threads incrementing counters with `yield_now` both
    progress; a thread that spins without yielding does not starve another (its counter advances
    within 200 ticks); `sleep_ms(30)` sleeps 25..=120 ticks (wide window, TCG slack); wait queue
    wakes a blocked thread; sleeping `Mutex` with 4 threads × 1000 increments gives exactly 4000;
    `Semaphore` limits concurrency; `join` returns the exit code; idle runs when nothing is ready
    (ticks advance while the main thread sleeps); every thread stack has a registered guard;
    a thread that exits is reaped (PMM free frames return to baseline after join); nested
    `IrqMutex` inside a scheduler critical section restores IF; preemption from within a
    long-running test loop keeps the tick counter advancing.
