# Brief M1-T3 — kernel heap (`GlobalAlloc`) on top of the PMM

## Goal
`alloc::{vec, string, boxed, collections}` work inside the kernel, backed by frames from the PMM,
with stats, no leaks, and stress tests. Everything after this (ACPI tables, scheduler queues,
drivers) uses the heap.

## Applies
D2 (write the allocator yourself: no `linked_list_allocator`, no `buddy_system_allocator`), D3, D5.

## Where things are
kernel/src/mm/ holds addr.rs, hhdm.rs, bitmap.rs, pmm.rs from M1-T2 — use the PMM API as it
actually exists there (brief M1-T2 named it `alloc_frame`, `alloc_frame_zeroed`,
`alloc_contiguous(n, align)`, `free_frame`, `free_contiguous`, `stats`). New code:
kernel/src/mm/heap.rs (+ heap/slab.rs if it grows). Tests live with the other `#[test_case]`s;
start a kernel/src/tests/ module tree if test_main.rs is near 600 lines.

## Design
1. Size-class (slab) allocator for small requests: classes 16, 32, 64, 128, 256, 512, 1024, 2048
   bytes. Each class owns a list of 4 KiB slabs obtained from `alloc_frame()` and addressed through
   the HHDM. Free objects form an intrusive singly linked free list inside the slab memory. Keep a
   per-slab header (or a side table keyed by frame) with the class, object count, and free count so a
   slab whose objects are all free is returned to the PMM (`free_frame`). Requests with `align >
   size` round up to the class that satisfies the alignment (all class objects are naturally
   aligned to their size because slabs are frame-aligned and object sizes are powers of two).
2. Large requests (> 2048 bytes, or align > 2048): allocate `ceil(size / 4096)` contiguous frames
   with `alloc_contiguous(n, align_frames)` and hand out the HHDM address. Record `n` so `dealloc`
   can `free_contiguous` (a small fixed-capacity table of (ptr, n) pairs protected by the same lock
   is fine for now; note a `// TODO(M1-T4)`: move large objects to a virtual heap region once the
   VMM exists). Alignment above 4096 is unsupported: return null (never panic inside `alloc`).
3. `pub struct KernelHeap` behind a `spin::Mutex`, registered as `#[global_allocator]`.
   `unsafe impl GlobalAlloc`: `alloc`, `dealloc`, `alloc_zeroed` (zero only what is needed),
   `realloc` (default is fine, but a same-class fast path is welcome). `extern crate alloc;` in
   lib.rs. Allocation failure returns null; the default no_std handler then panics with a clear
   message, which the panic path already reports.
4. Stats: `HeapStats { bytes_in_use, small_objects_in_use, slabs, large_objects, large_frames }`
   via `heap::stats()`. Boot log: `[heap] ready: 8 size classes, large objects via PMM`.
5. Init order (both binaries): serial → gdt → idt → pmm → heap → rest.
6. Tests (`#[test_case]`, ≥ 8 new): `Box<u64>` round trip; `Vec<u64>` push 10 000 and sum;
   `alloc::format!` builds the expected string; `BTreeMap<u32, u32>` with 1 000 inserts and lookups;
   `Layout::from_size_align(64, 64)` and `(4096, 4096)` return correctly aligned pointers;
   a 1 MiB allocation is writable end to end and the PMM free-frame count returns to its previous
   value after drop; 10 000 interleaved small allocs and frees leave both heap `bytes_in_use` and
   PMM free frames exactly where they started; a Vec that grows across size classes keeps its
   contents; a deterministic LCG stress of 5 000 alloc/free operations with sizes 1..8192 where
   every live buffer is filled with a per-buffer byte pattern and verified before free (catches
   overlap and corruption).

## Acceptance (run all; report exit codes)
- `source scripts/env.sh && gmake test` → 0; serial shows `[heap] ready` and `[ok] tests passed (N)` with N ≥ 27
- `gmake fault-test`, `gmake df-test`, `gmake bios-test`, `gmake panic-test`, `gmake shot` → 0 each
- `gmake lint` → 0; `gmake build` warning-free
- every `unsafe` block has a `// SAFETY:` comment
