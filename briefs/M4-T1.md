# Brief M4-T1 — PS/2 mouse, unified input events, poll(), framebuffer handoff with write-combining

## Goal
The kernel gives a userspace display server what it needs from the hardware side: mouse and
keyboard as one event stream, a way to wait on many descriptors at once, and exclusive,
write-combined access to the framebuffer, with the kernel console stepping aside and coming back.

## Applies
D2, D9, D10 (userspace display server; app crashes never take the OS down), D14, D16, D17.

## Where things are
i8042 and keyboard: kernel/src/drivers/ps2/. Devices and fds: kernel/src/fs/devfs.rs,
kernel/src/fs/vfs/fd.rs, pipes kernel/src/fs/pipe.rs (M3-T3). VMM: kernel/src/mm/vmm/.
Console: kernel/src/console/. usermem: kernel/src/proc/usermem.rs. New: kernel/src/drivers/ps2/mouse.rs,
kernel/src/input/mod.rs, kernel/src/drivers/fb.rs, kernel/src/arch/x86_64/pat.rs,
kernel/src/syscall/poll.rs, tests in kernel/src/test_cases/{mouse,input,poll}.rs.

## Design
1. PS/2 mouse on the i8042 aux port: enable port 2, aux IRQ 12 through the I/O APIC, reset and
   self-test with the 1000 ms budget, set defaults, IntelliMouse detection (sample rates 200, 100,
   80 then read ID 3 → 4-byte packets with wheel), enable reporting. Packet sync on byte-0 bit 3,
   discard on overflow bits, resync after a lost byte. The shared controller: aux commands through
   0xD4, and each IRQ handler consumes port 0x60 only when status bit 5 says the byte is its own.
2. Input events: `InputEvent { time_ms, kind }` with Key {code, pressed, mods, ch},
   MouseMove {dx, dy}, MouseButton {button, pressed}, Wheel {delta}; a 1024-entry ring filled from
   IRQ context without locks or allocation. `/dev/input` delivers fixed-size records to one owner at
   a time; while owned, keyboard bytes stop flowing to /dev/console; ownership returns to the
   console when the owner closes it or dies.
3. `poll(fds, nfds, timeout_ms)` syscall with POLLIN / POLLOUT / POLLHUP / POLLERR for pipes,
   /dev/input, /dev/console and (next task) channels; a readiness-notification hook on each object
   that wakes pollers; timeout 0 = non-blocking, -1 = forever. libotter `poll` wrapper.
4. PAT: program IA32_PAT so one PAT index is write-combining; `PageFlags::WRITE_COMBINING` maps to
   it. `/dev/fb0`: `fb_info(fd)` returns width, height, pitch, bpp, pixel format;
   `mmap_fd(fd, len, prot)` maps the framebuffer's physical range write-combined into the caller.
   Opening fb0 is exclusive; the kernel console stops drawing (keeps its shadow buffer and serial)
   and redraws everything when the owner closes it or dies. A kernel panic always takes the screen
   back and draws.
5. libotter: `input::Input::open()`, `read_events()`, `fb::Framebuffer::acquire()` exposing the
   info and a `&mut [u32]` pixel slice, `poll`.
6. QMP harness: `scripts/qemu.py --mouse` accepting a script like `move:40,-20;click:left;wheel:1`
   using `input-send-event` (relative motion, buttons, wheel), sent after a serial readiness line.

## Tests
Kernel (`#[test_case]`, >= 8): 3- and 4-byte packet decoding, sign and overflow bits, resync after a
dropped byte, event ring overflow counting, poll readiness for a pipe (ready, not ready, hangup),
poll timeout accuracy within a wide window, PAT MSR contains a WC entry, fb0 exclusivity (second open
gets EBUSY). Userspace utest (>= 5): open /dev/input and receive the injected mouse move, click and a
key within 2 s (`gmake test` injects them); poll on two pipes wakes for the right one; fb_info
plausible; mmap fb0, draw a 50x50 amber square, release, and the console redraws (serial marker);
killed fb owner releases the screen.
