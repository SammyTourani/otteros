# Brief M7-T5 — Otter runs inside OtterOS (boot-module model, userspace inference, golden check)

## Goal
The first time a language model runs inside the OS: the tiny test model arrives as a Limine
module (D31), the kernel maps it read-only into a userspace program, and `/bin/otter-run` uses
the host-tested crates (`otter-llm` loader, tokenizer and forward pass) to reproduce the host's
transformers reference: tokenization of 20 prompts, top-10 logits at every position of three
prompts, and 32-token greedy continuations. The comparison happens on the host
(`scripts/llm_check.py`, orchestrator-written oracle): OtterOS only knows the prompt texts.

## Applies
D21 (userspace inference crate), D31 (boot modules), D2 (path dependencies on crates/),
CLAUDE.md conventions (`// SAFETY:` everywhere, zero warnings). Never run git
checkout/restore/reset/stash/clean. Do not edit `scripts/llm_check.py`.

## Design
1. Kernel — boot modules: collect every Limine module with its cmdline as its name (the initramfs
   is the module named `initramfs`, as today). New syscall `module_map(name_ptr, name_len,
   len_out_ptr) -> address` (next free number; document it in SYSCALLS.md): maps the module's
   physical pages read-only, user-accessible, no-execute into the caller at a fresh address, writes
   its byte length to `*len_out_ptr`, returns the address; ENOENT for an unknown name, EFAULT for
   bad pointers, EPERM for names starting with `anthropic` (the key is for the agent service only,
   D31). Module memory is never freed or reused by the PMM. libotter wrapper
   `module_map(name) -> Result<&'static [u8], Errno>`.
2. Userspace — `user/otter-run` (new binary in the user workspace, path dependency on
   `../crates/otter-llm`): `otter-run --golden --detailed p01_hello,p04_numbers_float,p11_chatml_math
   --steps 32` maps module `model`, loads it (`Model::load`, zero copy), builds the tokenizer, and
   prints one `[otter-json] {...}` line (compact JSON, logits with at least 6 decimals) per result:
   - for every prompt of `tools/otter-convert/tests/fixtures/prompts/prompts.json` (embedded with
     `include_str!`; parse it with otter-json): `{"kind":"tokenize","id":ID,"ids":[...]}`;
   - for each detailed prompt: feed its token ids one at a time through a `Session`; after each
     position p print `{"kind":"logits","id":ID,"position":p,"top10":[[token,logit],...]}` (the ten
     largest logits, descending); then greedy decoding for `--steps` tokens, where the first new
     token is the argmax of the last prompt position's logits and every chosen token is fed exactly
     once: `{"kind":"greedy","id":ID,"tokens":[...]}`;
   - finally `[otter] golden run: N forward passes in T ms (R tok/s)`.
   Exit 0. The program must not contain or read any golden/reference numbers.
3. Test image and target: `build/otteros-llm.iso` = the test kernel + initramfs (with
   `/bin/otter-run`) + module `model` = `$OTTEROS_MODEL_DIR/tiny-random.f32.otm` (fail with a clear
   message naming `gmake models` when it is missing); Limine cmdline `llmtest`, on which init runs
   `/bin/otter-run --golden --detailed p01_hello,p04_numbers_float,p11_chatml_math --steps 32` and
   exits QEMU with its status (the existing test-exit syscall). `gmake llm-test` boots it via
   `scripts/qemu.py --mode test` (expecting success) and then runs
   `scripts/llm_check.py artifacts/serial.log tools/otter-convert/tests/fixtures/tiny-random/golden.json`.
   Add `llm-test` to `scripts/check.sh`. A `gmake model-test` target (not in the gate) does the same
   with `SmolLM2-135M-Instruct.f32.otm` and `.../smollm2/golden.json` and a longer timeout.

## Acceptance
- `source scripts/env.sh && gmake check` → every target PASS including `llm-test`
  (`[llm_check] ... 0 mismatches`).
- `gmake model-test` passes (report its tok/s line); `gmake lint` clean.
