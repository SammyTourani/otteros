# Brief M3-T2 — partitions (MBR/GPT), FAT32 read/write with long names, CMOS RTC

> Update 2026-09-24: the partition and FAT32 logic is being built and host-tested as the pure crate
> `crates/otter-fat` (brief M3-T2a). This task then wires it into the kernel: `BlockDevice` for
> virtio-blk partitions, mount at boot, the RTC as its `Clock`, the `fat-test` gate target.

## Goal
OtterOS reads and writes FAT32 volumes that macOS and Linux tools create and check: files,
directories, long file names, growth and truncation, with the on-disk structure staying valid
(`fsck.fat` clean). Timestamps come from the CMOS real-time clock.

## Applies
D2 (no `fatfs`), D7 (FAT32 on disk; USB sticks are FAT), D14, D17.

## Where things are
Block layer and cache: kernel/src/block/ (`BlockDevice`, cached reads/writes, `sync`), the
virtio-blk device `vda`. Test image script: scripts/mkdisk.py. New code: kernel/src/block/part.rs
(MBR, GPT), kernel/src/fs/fat32/{mod,bpb,fat,dir,lfn,file}.rs, kernel/src/time/rtc.rs (or
kernel/src/rtc.rs), tests in kernel/src/test_cases/fat32.rs, harness scripts/fat_check.sh.

## Design
1. Partitions: MBR (4 primary entries, type 0x0B/0x0C FAT32, 0xEE protective → GPT), GPT (header
   CRC32 and entry-array CRC32 verified, Microsoft basic data GUID and EFI system GUID recognised),
   and "superfloppy" volumes with no table (BPB at LBA 0). A `Partition` is itself a
   `BlockDevice` (offset + length, bounds-checked). Log `[part] vda1: FAT32 LBA .. size ..`.
2. FAT32 core: BPB validation (bytes/sector 512–4096, sectors/cluster power of two, FAT count 2,
   FAT32 signature, root cluster), FSInfo (free count and next-free hint, both treated as hints
   and validated), FAT entry read/write with the top 4 bits preserved, both FAT copies updated,
   cluster chain walk with loop detection (chain longer than cluster count → corruption error),
   cluster allocation (next-free hint, zero new directory clusters), freeing chains.
3. Directories: 32-byte entries, 8.3 names with case flags (NT byte 0x0C), long file names
   (LFN entries, UCS-2 ↔ UTF-8, checksum validation, orphan LFN entries ignored), deleted entries
   (0xE5), end marker (0x00), `.` and `..`, creating entries with the shortest valid 8.3 alias
   (`LONGFI~1.TXT` generation with collision numbering), directory growth by a cluster when full.
4. Files: `Fat32Fs` API used by the VFS in the next task: `lookup(dir, name)`, `readdir(dir)`,
   `read(file, offset, buf)`, `write(file, offset, buf)` (extends with new clusters, updates size
   and mtime), `truncate(file, len)`, `create(dir, name)`, `mkdir(dir, name)`, `unlink`, `rmdir`
   (only when empty), `rename` within the same volume, `stat` (size, is_dir, times). All errors are
   an `FsError` enum mapped to errno later. Sequential reads of large files must use multi-cluster
   runs (contiguous clusters coalesced into one block request) — M7 streams model weights this way.
5. RTC: read CMOS (0x70/0x71) with the update-in-progress check and double-read consistency, BCD
   and 12/24-hour handling, century from the FADT century register when present; `rtc::now()` →
   `DateTime`; FAT timestamps from it. Log `[rtc] 2026-..-.. ..:..:.. UTC`.
6. Harness: `scripts/mkdisk.py` gains `--fat32` that builds `build/fat.img` (64 MiB, MBR with one
   FAT32 partition) using `mformat`/`mcopy`/`mmd` (mtools) with fixtures: `/HELLO.TXT`,
   `/Long File Name With Spaces.txt`, `/dir/sub/deep.txt`, `/big.bin` (5 MiB, deterministic
   pattern), a directory with 300 files (forces multi-cluster directories). Test mode
   `test fat32` runs the FAT tests, including writes under `/out/`. After QEMU exits,
   `scripts/fat_check.sh` runs `fsck.fat -n` on the partition (dosfstools; extract the partition
   with `dd` if fsck needs a bare volume) and `mtype`/`mdir` checks that the files OtterOS wrote
   have the expected content and names. `gmake fat-test` = build image, boot, host checks; add it
   to `gmake check`.
7. Tests (`#[test_case]`, >= 14 new): MBR and GPT parse (GPT header built in-memory with valid and
   corrupted CRCs); BPB rejects nonsense; read HELLO.TXT; LFN lookup and readdir return the exact
   long name; nested path lookup; big.bin content and read throughput (`[fat32] seq read MiB/s`);
   create + write + read back; append across a cluster boundary; truncate frees clusters (free count
   restored); mkdir + rmdir; unlink frees the chain; rename; 300-file directory listing; 8.3 alias
   collision numbering; FSInfo free count equals a full FAT scan after the write tests; RTC year
   is >= 2026 in QEMU.
