# Brief M1-T7 — framebuffer text console, unified logging, milestone gate

## Goal
Everything the kernel logs appears on screen as well as on serial, with scrolling, colours and a
cursor, so `gmake run` shows a real boot log a human can read; and one make target runs every
check for the milestone.

## Applies
D2, D5, D11 (font licensing), D14 (panic path must not deadlock on the console lock).

## Where things are
kernel/src/framebuffer.rs (banner drawing, original 8x8 font in font8x8.rs), kernel/src/serial.rs
(`kprint!`/`kprintln!`, IrqMutex). New code: kernel/src/console/{mod,cell,ansi}.rs; framebuffer.rs
becomes a thin device layer (dimensions, pitch, blit rows).

## Design
1. Console model: a heap-allocated shadow buffer of cells (glyph, fg, bg) `cols × rows` plus a
   heap-allocated pixel back buffer; never read from the framebuffer (MMIO reads are slow). Glyphs
   rendered from the 8x8 font at 2x (16x16 cells) by default for readability; `console::set_scale(1)`
   available. Cursor drawn as an underline; hidden while drawing.
2. Behaviour: `\n`, `\r`, `\t` (to next multiple of 8), backspace (erase previous cell), wrap at
   the last column, scroll by one row (memmove the shadow + back buffer, blit only the dirty region
   to the framebuffer), clear screen. ANSI subset: `ESC[0m` reset, `ESC[1m` bold (bright fg),
   `ESC[30–37m`, `ESC[90–97m` foreground, `ESC[40–47m` background, `ESC[2J` clear, `ESC[H` home.
   Default palette: dark background, light-grey text; `[module]` prefixes are not special-cased.
3. Logging: `kprint!`/`kprintln!` write to serial and, once the console exists, to the console.
   Keep serial as the first sink (it is what the tests read). The panic path uses `try_lock` on the
   console: if it gets the lock it prints the panic in red on screen; if not, serial only.
   Boot-time messages emitted before the console exists are kept in a small static ring and
   replayed onto the console when it comes up, so the on-screen log is complete.
4. Replace the M0 banner drawing with console output: a title line (`OtterOS` in bold), the
   memory line, then the normal boot log; keep the `[ok] fb banner` serial line for `gmake shot`.
   Normal mode ends with the keyboard echo prompt from M1-T6 using the console.
5. `gmake check`: runs build, lint, test, bios-test, fault-test, df-test, stackoverflow-test,
   pmm-fault-tests, panic-test, shot in sequence, prints a one-line PASS/FAIL table, exits non-zero
   on any failure. README documents it as the milestone gate.
6. Tests (`#[test_case]`, ≥ 8 new; run against a console instance over an in-memory fake
   framebuffer so they do not depend on the real one): cursor advances per char; newline and
   carriage return; tab stops; wrap at column end; scrolling moves rows up and clears the last
   row; backspace erases; ANSI colour and reset parse into cell attributes and unknown sequences
   are ignored safely; the early-boot replay ring preserves message order.

## Acceptance (run all; report exit codes)
- `source scripts/env.sh && gmake check` → 0 with every row PASS; `gmake test` reports `[ok] tests passed (N)` with N ≥ 63
- `gmake shot` → artifacts/shot.png shows a multi-line boot log with the title line and at least 8 log lines (the orchestrator will look at the image)
- every `unsafe` block has a `// SAFETY:` comment
