# Brief M3-T1 — PCI(e) enumeration, virtio-blk, block layer with cache

> Update 2026-09-24 (M3-T1b): the split-virtqueue logic, EVENT_IDX suppression and the virtio 1.x
> initialisation sequence are being built and host-tested as the pure crate `crates/otter-virtio`
> (brief M3-T1c, including a concurrent device model on the weakly ordered ARM64 host). The kernel
> driver replaces kernel/src/drivers/virtio/queue.rs with it and only supplies DMA memory (physical +
> HHDM virtual addresses), the PCI capability mapping (`Transport` impl over MMIO) and MSI-X wiring.

## Goal
The kernel discovers devices on the PCI bus through ACPI MCFG (ECAM), drives a modern virtio-blk
disk with interrupts, and exposes a block-device layer with a write-back cache that later file
systems use. A data disk image built on the Mac is read and written from OtterOS.

## Applies
D2 (no `virtio-drivers`, no `pci` crates), D5, D7 (virtio-blk first; FAT32 next), D14, D15 (MMIO
windows through the HHDM or the kernel dynamic region), D17 (blocking I/O puts the calling thread
to sleep on a WaitQueue).

## Where things are
ACPI tables: kernel/src/acpi/ (MCFG appears in the boot log: `[acpi] MCFG len=60`). IRQs:
kernel/src/arch/x86_64/{irq,ioapic,lapic}.rs. Scheduler/wait queues: kernel/src/sched/. VMM
mapping API for MMIO: kernel/src/mm/vmm.rs (`map_range` with NO_CACHE). New code:
kernel/src/drivers/pci/{mod,ecam,config,msi}.rs, kernel/src/drivers/virtio/{mod,pci_transport,
queue,blk}.rs, kernel/src/block/{mod,cache}.rs, tests in kernel/src/test_cases/{pci,block}.rs.

## Design
1. PCI: parse MCFG allocations (segment, bus range, ECAM base); config space access via ECAM
   (map the window uncached); legacy port 0xCF8/0xCFC fallback when MCFG is absent. Recursive scan
   (bridges: secondary bus), functions 0–7 when multifunction. `PciDevice { bdf, vendor, device,
   class, subclass, prog_if, header_type, bars, irq_line, interrupt_pin, capabilities }`. BAR
   decoding: I/O vs memory, 32/64-bit, size probing (write all-ones, restore), prefetchable flag.
   Capability list walk (MSI 0x05, MSI-X 0x11, vendor-specific 0x09 for virtio). Log one line per
   device: `[pci] 00:03.0 1af4:1042 class 01.00 virtio-blk`. Keep a global device list.
2. Interrupts: MSI-X preferred (program a table entry: LAPIC address, vector, unmask), MSI next,
   legacy INTx last (via the I/O APIC with the MADT/ISA-default polarity helpers; PCI INTx is
   level-triggered active-low; note that ACPI _PRT is not parsed, so INTx routing uses the
   `interrupt_line` from config space and is QEMU-only). Allocate vectors from a simple vector
   allocator in irq.rs (48..=239 for devices).
3. virtio (1.x modern, PCI transport): find common/notify/ISR/device config structures through the
   vendor capabilities; feature negotiation (VERSION_1 required; blk: SIZE_MAX, SEG_MAX, BLK_SIZE,
   FLUSH if offered; reject others), split virtqueues (descriptor table, avail and used rings) in
   PMM frames with physical addresses; `queue_notify`; completion via MSI-X interrupt that wakes
   the waiting thread; timeouts (5 s) on every request so a missing interrupt fails loudly.
4. virtio-blk: capacity, sector size 512, read/write/flush requests with 3-descriptor chains
   (header, data, status), up to 128 KiB per request, status byte checked. `BlockDevice` trait:
   `read_blocks(lba, &mut [u8])`, `write_blocks(lba, &[u8])`, `flush()`, `block_size()`,
   `block_count()`, `name()`. Registry of block devices (`vda`, `vdb`, ...).
5. Block cache (`block/cache.rs`): 4 KiB cache blocks, LRU, fixed budget (8 MiB default), write-back
   with dirty tracking, `sync()` writes dirty blocks in LBA order then flushes the device;
   read-ahead of the next 64 KiB on sequential access (M7 will read hundreds of MiB of model
   weights through this path, so sequential throughput matters). Thread-safe with a sleeping Mutex.
6. Harness: `scripts/mkdisk.py` creates `build/data.img` (64 MiB) with a known pattern in the first
   16 MiB (sector n starts with the ASCII string `OTTERDISK n` followed by a deterministic byte
   pattern). QEMU gets `-drive file=build/data.img,if=none,id=data,format=raw -device
   virtio-blk-pci,drive=data,disable-legacy=on` for test, bios-test and shot. Tests must not depend
   on writes surviving between runs: the image is regenerated before each test boot.
7. Tests (`#[test_case]`, >= 10 new): PCI finds the host bridge and the virtio-blk device with the
   right vendor/device IDs; BAR sizes are powers of two; capability list contains the virtio
   structures; MSI-X is enabled for the disk; read sector 0 and sector 1000 match the pattern;
   a 1 MiB read equals the concatenation of 256 single 4 KiB reads; write/read-back of a scratch
   region (last 1 MiB) with a random pattern; cache hit counter increases on a repeated read;
   `sync()` leaves no dirty blocks; concurrent reads from 4 threads return correct data; a request
   timeout path is exercised with a fake device or a forced-missing interrupt flag.
