# Brief M7-T1 — Otter foundations: `otter-json`, the model converter, and an independent reference

## Goal
Everything the in-OS language model needs before its runtime exists: a JSON library, a converter
from Hugging Face checkpoints to OtterOS's own `.otm` format (f32 and Q8), and golden reference
data produced by the canonical Hugging Face `transformers` implementation, so every later runtime
step is judged against an independent oracle rather than against itself.

## Applies
D2, D21 (Llama-family only, Q8 groups of 32, Apache-2.0/MIT weights, weights never committed, golden
logits from an independent reference), D27, D28 (all downloads and the Python environment on the
SSD: `OTTEROS_MODEL_DIR=/Volumes/SammyDisk/models/otteros`, venv under
`/Volumes/SammyDisk/venvs/otteros`).

## Scope and boundaries (another agent works in kernel/ and user/ concurrently)
New: `crates/otter-json/`, `tools/otter-convert/` (a host binary crate, its own small cargo project or
a member of a new `tools/` workspace; zero external dependencies, path dependency on otter-json),
`scripts/llm-venv.sh`, `scripts/llm-reference.py`, `scripts/fetch-models.sh`, golden fixtures under
`crates/otter-llm-fixtures/` or `tools/otter-convert/tests/fixtures/` (small files only). Do not
touch kernel/, user/, GNUmakefile. Do not run gmake or QEMU.

## Design
1. `otter-json` (no_std + alloc, pure): RFC 8259 parser to a DOM (`Value` with objects preserving key
   order), strict (no trailing commas, no comments), full string escapes incl. surrogate pairs,
   numbers as i64/u64/f64 with exact integer handling, depth limit, byte-offset error messages; a
   serializer (compact and pretty, correct escaping) for M9's API requests; fast enough to parse a
   10 MB tokenizer.json in well under a second on the host. Tests incl. the JSONTestSuite
   (github.com/nst/JSONTestSuite, `y_`/`n_` cases must pass/fail as labelled; report `i_` behaviour).
2. `.otm` format (document it in `tools/otter-convert/FORMAT.md`): little-endian header with magic
   and version; model config (vocab, dim, layers, heads, kv heads, head dim, hidden dim, rope theta,
   norm eps, max context, tied embeddings, qkv bias flag, qk-norm flag); tokenizer section (vocab as
   byte strings after GPT-2 byte-to-unicode reversal, merges as id pairs with ranks, special tokens,
   BOS/EOS ids, pre-tokenizer kind); chat template kind (ChatML for SmolLM2 and Qwen families,
   with the exact literal strings); tensor table (name, dtype, shape, offset) with 64-byte aligned
   data; dtypes F32 and Q8_0 (blocks of 32 int8 with one f32 scale).
3. `otter-convert`: reads a Hugging Face model directory (config.json, safetensors in BF16/F16/F32,
   tokenizer.json, tokenizer_config.json), validates the architecture (LlamaForCausalLM,
   Qwen2ForCausalLM, Qwen3ForCausalLM; others rejected with a clear message), writes `.otm` with
   `--dtype f32|q8`. `--tiny-random SEED` writes a deterministic tiny Llama-style model (e.g. dim 64,
   2 layers, 4 heads, 2 kv heads, hidden 176, vocab taken from a real tokenizer or 512) as
   safetensors + config so the reference script can load it too.
4. Reference environment: `scripts/llm-venv.sh` creates `/Volumes/SammyDisk/venvs/otteros` with
   CPU `torch` and `transformers` (pip cache is already on the SSD). `scripts/fetch-models.sh`
   downloads HuggingFaceTB/SmolLM2-135M-Instruct (Apache-2.0) into `$OTTEROS_MODEL_DIR`, pinning
   file SHA-256s. `scripts/llm-reference.py` loads a model with `transformers` in float32 and writes
   golden JSON fixtures: token ids for 20 prompts (plain text and ChatML-formatted, incl.
   punctuation, numbers, whitespace runs, non-ASCII), the top-10 logits at every position of 3
   prompts, and 32-token greedy continuations. Run it for the tiny random model and for
   SmolLM2-135M-Instruct.
5. Converter self-checks (host tests): f32 export round-trips every tensor bit-exactly against the
   safetensors source; Q8_0 dequantization error within the expected bound; tokenizer section
   reproduces the reference token ids for all 20 prompts using a straightforward reference BPE
   implemented inside the converter's tests (this BPE becomes the spec for the runtime's tokenizer).

## Acceptance (run all; report exit codes)
- `cd crates && cargo test -p otter-json` -> 0 with the JSONTestSuite results reported
- converter tests -> 0; `.otm` files for the tiny model (f32, q8) and SmolLM2-135M-Instruct (f32, q8) exist in `$OTTEROS_MODEL_DIR` with sizes reported
- golden fixtures committed (small), SHA-256 pins present, nothing large committed, no downloads on the internal disk
- clippy clean for the new crates; `otter-json` builds for `x86_64-unknown-none`
